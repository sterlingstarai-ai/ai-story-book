# 운영 가상 동화 검증 설계 — 2026-11-03

운영 제공자 전환은 별도로 성공했다. 기존 일회용 환경에서 실제 가상 4쪽 동화가 완성됐지만, 이는 운영 전체 경로 검증이 아니다. 운영의 전 사용자 합산 하루 생성 한도는 1권으로 확인됐고, 격리 시험에만 적용된 HTTP 호출 제한 장치는 운영 worker에 설치돼 있지 않다. 따라서 독립된 가상 계정을 만들어도 현재 방식으로는 사용자 할당량을 보존하면서 글·그림 호출 상한을 보장할 수 없다. **이 문서는 설계이며 운영 계정 생성이나 설정 변경을 수행하지 않는다.**

## 최소 구현

1. 별도 관리자 인증과 제한된 서버 측 작업으로 가상 run을 생성한다. run은 무작위 소유 계정, 작업 ID, 허용된 단일 가상 입력, 만료 시각을 서버에서 발급·고정한다. 일반 요청의 `X-User-Key`나 요청 본문만으로 run 지정, 권한 획득, 한도 우회가 가능해서는 안 된다. 인증 비밀과 시험 계정 키는 로그와 명령행에 노출하지 않는다.
2. 정규 사용자 전역 예산과 독립된 시험 예산을 두고, 단 한 권의 예약을 원자적으로 처리한다. 사용자 예산의 잔량을 변경하거나 테스트 실패 시 임의로 되돌리지 않는다. 시험 허용 기간과 계정·작업 범위를 명시하고 운영 정책을 회피하는 공개 API를 만들지 않는다.
3. API의 가상 캐릭터 생성부터 worker의 검수·보완·재시도까지 모든 유료 글·그림 전송 직전에 run별 역할 및 허용 모델을 확인하고, 공용 Redis 또는 DB에서 내구성 있는 원자 예약으로 호출 횟수를 차감한다. 예산 저장소가 없거나 식별이 불확실하면 공급자 호출 전에 실패한다. 동일 요청이 실제 전송됐는지 불확실할 때도 예약을 환급하거나 자동으로 다시 시도하지 않는다. 병렬 그림 생성과 worker 재시작에서도 합계가 유지되어야 한다. 토큰·이미지 크기 제한도 별도로 검증하며 호출 횟수를 과금 상한으로 표현하지 않는다.
4. 가상 계정과 그 작업만 API로 조회하고 생성 산출물은 소유 범위에서만 검토한다. 지원되는 계정 삭제·동의 철회 경로를 이용해 완료 및 보류 상태를 확인한다. 감사·동의 철회·인증 폐기 기록은 기존 보존 정책에 따라 남기고, 실패하거나 소유 범위를 확정할 수 없는 데이터는 임의 삭제하지 않는다. 원장과 스토리지 비동기 파기 완료는 삭제 요청의 HTTP 성공과 구별한다.
5. 도입 전 일반 계정의 테스트 권한 위조 거부, 동시 예약·서버 강제 종료·타임아웃·재전달·공급자 오류에 대한 상한 불변식, 정규 사용자 예산 불변, 데이터 소유권·실제 삭제와 파기 대기 상태를 합성 환경에서 확인한다. 운영 배포 후에는 소액·가상 입력 한 건만 수행하고 불명확하면 자동 반복하지 않는다.

별도로 운영 readiness는 성공 관측이 86,400초 후 만료될 수 있다. 이 테스트를 주기적 유료 호출이나 영구 healthy 신호로 대체하지 않는다. 최신 개인정보 삭제·동의 철회·인증 폐기의 실제 운영 복원 완전성, 백업 중단 없는 운영, iOS 생성부터 전체 낭독 및 실제 그림 품질 검토는 별도 출시 조건이다.
