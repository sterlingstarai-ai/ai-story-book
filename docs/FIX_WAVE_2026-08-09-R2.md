## 1. 🟡 A1-R — 저장된 잡 에러가 원문 그대로 서빙되던 문제

### red 증거 (수정 전)
덤프를 가진 잡 행을 시드해 상태 조회:
```
AssertionError: 저장된 잡 에러 원문이 서빙됐다(A1-R 회귀): 'pydantic' 노출
{"job_id":"job_hyg_288df00f8c","status":"failed",...,"error":{"code":"LLM_JSON_INVALID",
 "message":"응답 검증 실패: 2 validation errors for RewriteResult\npage\n  Field required
  [type=missing, input_value={'title': '용감한 토끼', 'pages': ['비밀 원문 조각']}, ...]
  For further information visit https://errors.pydantic.dev/2.10/v/missing"}}
```
`input_value` 안의 **모델 응답 원문 조각**까지 그대로 나갔다.

### 수정 — H2 읽기 경로 교훈을 그대로 적용(이중 방어)

| 층 | 내용 | 위치 |
|----|------|------|
| **규칙 단일화** | `client_safe_message()` / `client_safe_details()` 를 `core/errors.py` 로 이관. A1 의 `sanitize_domain_error` 도 여기에 위임한다 — **규칙이 두 벌이었던 것이 A1-R 의 근본 원인**이다. | `src/core/errors.py`, `src/main.py` |
| **(a) 서빙 시점 (load-bearing)** | 잡 상태 응답의 `error.message` 를 같은 규칙으로 위생 처리 → **이미 DB 에 저장된 원문 행도 새지 않는다** | `src/routers/books.py` |
| **(b) 저장 시점 (2차 방어)** | 워커·오케스트레이터·regen/inpaint 실패 저장이 일반 문구만 저장. 원문은 로그로만 | `src/services/tasks.py`, `src/services/orchestrator.py`, `src/routers/books.py` |

**부수 개선(요청 항목 — error.code 정보성 유지)**: Celery 실패 마킹(`_mark_job_failed_async`)이 **error_code 를 아예 저장하지 않아** 상태 조회에 `error: null` 이 나가던 것을 함께 고쳤다. 예외에서 도메인 코드를 도출(`_error_code_of`)해 저장한다 → 클라이언트가 재시도 가능 여부를 판단할 수 있다.

### green + 회귀 (`tests/test_job_error_hygiene.py`, 5종)
- 저장된 덤프 행 → 응답에 `pydantic`·`input_value`·`errors.pydantic.dev`·`RewriteResult`·원문 조각 **부재**
- **error.code 정보성 유지**: `LLM_TIMEOUT`·`IMAGE_RATE_LIMIT`·`STORAGE_UPLOAD_FAILED`·`QUEUE_FAILED` 가 뭉개지지 않음
- `SAFETY_*` 는 사용자 조치 가능 문구라 **원문 유지**(일반화 금지)
- enum 밖 코드(job_monitor 의 `SLA_BREACH` 등)·`None` 도 안전하게 일반 문구로 폴백
- 저장 시점: `_mark_job_failed_async` 가 원문을 저장하지 않음

## 4. ⚠️ 라이브 검증 중 발견 — **M2 를 제가 한 곳만 고쳤다**

라이브 재검증이 일일 생성 예산에 걸리면서 드러났다:
```json
{"error":{"code":"daily_limit_exceeded", ...}}   ← 소문자
```
**M2 는 봉투 코드 규약 통일이었는데 `rate_limit.py` 한 곳만 고쳤고, 같은 소문자 코드가 3곳 더 있었다**(예산·과부하 가드). 새 결함이 아니라 **제 M2 수정의 미완결**이므로 이번에 마감했다.

| 위치 | 이전 | 이후 |
|------|------|------|
| 전역 일일 예산 초과 (429) | `service_budget_exceeded` | `SERVICE_BUDGET_EXCEEDED` |
| 사용자 일일 한도 초과 (429) | `daily_limit_exceeded` | `DAILY_LIMIT_EXCEEDED` |
| 시스템 과부하 (503) | `system_overloaded` | `SYSTEM_OVERLOADED` |

셋 다 `HTTPException(detail={...})` 수제 봉투였다 → `APIError` 로 전환(코드 규약·details·headers 처리가 한 곳으로). `Retry-After` 헤더는 유지(테스트로 고정).

**재발 방지 — 구조 불변식 2종**(`tests/test_rate_limit_envelope.py`):
1. `src/` 의 모든 `error_code="..."` 리터럴이 UPPER_SNAKE
2. 라우터가 `HTTPException(detail={"error": ...})` 로 봉투를 **직접 만들지 않는다** — 소문자가 새어 들어온 바로 그 경로를 구조적으로 막는다

**red-proof**: 코드 하나를 소문자로 되돌리면
`AssertionError: UPPER_SNAKE 가 아닌 봉투 코드: ["books.py:511 'daily_limit_exceeded'"]`

기존 테스트 3건이 소문자를 계약으로 고정하고 있어 정본으로 갱신했다(`test_error_responses.py` 2건, `test_cost_budget.py` 1건) — M2 때 `test_security.py` 와 같은 패턴.
