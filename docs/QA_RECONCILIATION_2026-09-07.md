# 2026-09-07 독립 QA 두 보고서 통합 검토

검토 대상은 사용자가 전달한 보고서 캡처 6장·실제 오류 화면 1장과 추가 HTML 보고서다. 사용자 제공 자료는 증거로 다루었으며, 보고서의 결론을 재현 여부와 분리했다. 비공개 원본은 `docs/acceptance/2026-09-07-combined-qa/`에 보존했다.

**스토어에 등록하지 않았기 때문에 책이 실패한 것이 아니다.** 첫 보고서는 실제 생성 뒤 삽화 보완 실패, 두 번째는 OpenAI 잔액 부족으로 이미지 생성 전 실패했다. 두 보고서 모두 앱의 상태 조회가 서버의 기본 요청 한도와 충돌했다. 코드 검사 통과와 실제 제공자·운영 구성·출시 준비를 한 가지 성공으로 취급했던 이전 검증 범위를 보완한다.

## 추가 검토 판단

- 동의 전에 앱의 가치를 설명하는 순서 변경은 UX 제안이다. 보호자 동의 → 온보딩이라는 현재 제품 계약을 유지하면서 필수/선택 구분, 전문 열람, 스크롤 가시성을 고쳤다. 실제 사용자 이탈률 개선을 측정했다고 주장하지 않는다.
- 아이 프로필이 없을 때 사진 없이도 만들 수 있는 기존 경로는 유지한다. 현재 프로필 표시와 이름 자동 사용·수정 동선을 제공하며, 별도의 불필요한 생년월일 입력을 강제하지 않는다.
- 일반 업로드는 앱에서 사진을 축소한다. 직접 API에 16MP를 넘겨 보냈을 때도 해상도 초과라는 정확한 안내를 반환하도록 수정하고 경계 테스트를 추가했다. 이 검사를 실제 카메라 실기기 검증으로 확대하지 않는다.
- 캐시 삭제를 점검하면서 사진 동의의 이전 상태를 확인하지 못해도 사진 미동의 저장을 강행하던 경로를 발견했다. 기존 사진 파생물을 확인 없이 지울 수 있어 조회가 회복된 뒤 진행하도록 바꿨다.

## 정책 문서의 완료 범위

앱의 두 전문은 `apps/mobile/assets/legal/`의 버전 있는 원본이다. `scripts/render_legal_documents.py`가 공개 검토용 HTML을 생성한다. 사용자에게 받은 공개 운영자·이메일을 반영했으며 기존 예시 이메일을 제거했다. 기존 한국어 사진 처리 동의 고지 자체를 임의의 법률 승인 문구로 바꾸지 않았다.

다음은 코드가 대신 확정할 수 없는 공개 전 확인 사항이다: 실제 운영 저장소·위탁 업체와 이전 국가/연락처/보유 기간, 운영·보안 기록 및 백업의 구체적인 보관 일정, 시행일과 최종 문구 검토. 문서는 현재 `review` 상태이며 공개 빌더와 외부 배포 사전 점검은 이를 승인 완료로 받아들이지 않는다. 사용자는 법률·제공자 문의를 직접 확인하기로 했고 OpenAI 상담 자동화는 삭제되었다.

정책 공개·앱 내 접근 요구를 확인한 공식 근거: [개인정보 보호법 제30조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398435), [Apple App Review Guidelines 5.1.1](https://developer.apple.com/app-store/review/guidelines/#privacy), [Google Play User Data](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en-GB). 기술 구현이나 문서 초안을 법률 검토 또는 스토어 승인으로 표시하지 않는다.

## 검증 기록

모바일 최종 전체 **574 통과·0 실패**, 커버리지 **65.39%**, Flutter 정적 분석 이상 없음이다. 실제 iOS에서 정책 열람·이미지 파일 삭제·완료 작업 열기·12쪽 읽기·큰 글씨 스크롤과 기존 시작/복귀·부모 확인 흐름을 검증했다. 집중 정책/동의37건도 통과했다.

API 최종 전체 **1,983 통과·0 실패·25 건너뜀**, Python3.12.12, 커버리지 **77.64%**이며 Ruff·환경 계약·OpenAPI 검사도 통과했다. 별도 PostgreSQL 경합4건과 실제 Redis 8분 상태 조회241건도 통과했다.

실제 자동 생성은 **529.58초·12쪽+표지·그림15회·LLM6회·자동 보완2라운드·상태 조회255회/429는0·추정US$1.204028**이었다. 모든13장을 글과 대조했다. 작은 장소 연속성 차이1건을 허용 수준으로 기록했고 수동 교정은0회다. 이 표본의 선택 학습 자료는 시험 도구 토큰 제한으로 외부 전송 전에 차단되어 미검증이다. 별도 사진 분석용 일반 JSON 요청의 추정$0.00032는 책 비용에 합산하지 않았다.

최종 원본 근거는 비공개 `docs/acceptance/2026-09-07-combined-qa/`, `docs/acceptance/2026-09-07-consolidated-live-book/`, `docs/acceptance/2026-09-07-consolidated-native/`에 보존했다. 중간 실패는 삭제하지 않는다. 첫 번째 보고서의 478초 실패와 두 번째 보고서의 잔액 부족 2회는 각각 별도 표본이며, 이번 결과로 과거 실패를 성공으로 바꾸지 않는다.

사용자가 직접 10달러를 충전했다. 이후 기존 LLM 키로 일반 JSON 요청 한 번이 HTTP 200으로 응답했다(입력 20·출력 12 토큰). 에이전트가 추가 결제를 제출한 횟수는 0이다. 이 응답은 API 이용 가능 관측이며 결제 화면의 정확한 잔액·자동 충전 설정을 직접 확인했다는 뜻은 아니다.


## 네이티브 화면 확인

1. **동의 전 정책 전문 — 통과.** 공개 웹 주소와 동의 기록이 없어도 전문 화면에 진입하고 2.35배 글씨로 마지막 조항까지 스크롤했다. 공개본 검토 상태를 숨기지 않는다.
2. **완성 상태 복구와 실제 책 읽기 — 통과.** 기존 완료 작업에 앱을 연결해 뷰어로 전환하고 본문12쪽의 실제 이미지를 전부 불러왔다. 앱에서 새 생성 요청이나 사진 업로드를 보내지 않았다. 전체529초 상태 조회는 별도 실제HTTP 검사, 앱 재시도는 별도 가상시계 검사다.
3. **큰 글씨와 하단 학습 버튼 — 통과.** 실제 본문을 그대로 사용하고 학습 버튼 노출 조건에만 합성 UI 데이터를 넣어 자연스러운 드래그로 마지막 줄까지 읽었다. 실제AI 학습자료가 있는 책을 검증했다는 뜻이 아니다.
4. **기기에 저장된 이미지 삭제 — 통과.** 네이티브 캐시 관리자에 실제 파일을 쓰고 정리 후 파일이 없어짐을 확인했다. 실패 시 재시작 복구는 실패 주입 회귀로 별도 검증했다.

## 정리 및 공개 설정 확인

전용 API·worker·Docker 컨테이너, 네이티브 시뮬레이터와 임시 파일 수신 프로세스의 정리를 완료했다. 사용자 브라우저·상담 창은 유지했고 별도 책·폴더 창은 열지 않았다. 프로젝트 메모리를 갱신했다.

현재 `infra/.env`를 읽은 외부 사전 검사는 **BLOCKED**다. 실제 운영 API·저장소·공개 정책 URL과 최종 문서가 준비되기 전에 공개로 넘어가지 못하게 하는 정상적인 차단이다. 로컬 `apps/api/.env`의 실제 AI 성공을 운영 배포 완료로 혼동하지 않는다. 사전 검사는 외부 API 호출·과금·배포를 하지 않았다.
