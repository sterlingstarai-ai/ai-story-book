# 등록 전 디자인·사용 흐름 검토

> 아래는 읽기·홈 중심의 앞선 검토 기록입니다. 앱 전체 20개 화면을 보완한 최신 결과와 검사 범위는 [전체 최종 디자인 검토](FINAL_DESIGN_REVIEW_2026-09-06.md)를 우선합니다.

2026-09-06. 사용자 요청에 따라 기존 디자인을 유지하면서 소비자 관점, 시각 디자인, UI/UX 역할의 에이전트가 독립적으로 검토했다. 실제 소비자 모집·인터뷰·사용성 조사 결과는 아니다. root는 실제 iOS Simulator와 격리된 API를 조작해 발견 사항을 확인하고 수정했다. 스토어 등록·업로드·심사 제출은 하지 않는다.

## 검토 결과와 반영

| 발견 | 판단·반영 |
|---|---|
| 제목과 그림의 겹침 | 본문 상단에 기기 안전 영역과 제목 바의 공간을 확보했다. 그림은 그 아래에서 시작한다. |
| 짧은 화면에서 본문 잘림 위험 | 그림과 본문을 조작부 사이에서 세로 스크롤할 수 있게 했다. 긴 본문·학습 콘텐츠·큰 글씨를 함께 검사한다. |
| 희미한 다음 버튼·쪽수·탭 | 페이지 이동을 보라색 버튼으로, 쪽수는 어두운 배경으로 표시한다. 하단 탭의 글자 대비와 선택 표시를 개선했다. |
| 홈에서 책 찾기 어려움 | 가장 최근 책과 읽기 동작을 먼저 보여 준다. 만들기·오늘 기록·부모 성장은 뒤에 배치한다. |
| 서재 관리 메뉴가 그림을 가림 | 흰색 작은 원으로 시각적 크기를 줄이고 64px 터치 영역은 유지한다. 책 제목은 최대 두 줄로 표시한다. |
| 마지막 장을 열자마자 축하창 표시 | 마지막 본문 아래의 **다 읽었어요**를 눌러야 완독을 기록하고 축하 안내를 표시한다. 단순 마지막 장 진입은 완독으로 기록하지 않는다. |
| 사용할 수 없는 스타일을 선택한 뒤 실패 | 서버가 실제 계정 정책으로 허용하는 스타일을 먼저 조회한다. 조회 실패 시 재시도를 안내하며 임의로 생성 권한을 넓히지 않는다. |
| 추천 주제 터치 영역과 오류 안내 | 추천 주제의 터치 영역을 64px로 확대하고 안전상 거절·하루 한도·연결 오류를 구분한다. |
| 음성 비활성인데 음성 의존 메뉴 표시 | 따라 읽기·수면 자동 읽기 진입을 서버의 오디오 지원 상태에 맞춘다. |
| 책을 닫을 때 수명주기 오류 | 읽기 시작의 API를 보관해 화면 정리 시 폐기된 Riverpod ref를 읽지 않도록 했다. |
| 보호자 확인 직후 실제 화면 오류 | 입력 컨트롤러를 다이얼로그 State가 소유하도록 수정했다. 입력·닫힘 전환 회귀와 기존 게이트 11개를 통과했고, 시뮬레이터에서 신고 접수·동화 복귀를 확인했다. 별도 새 인증 세션의 네이티브 회귀도 수행한다. |

흰 종이 배경·수채화·보라색 포인트·둥근 카드의 방향은 유지한다. 긴 한글 문단의 가운데 정렬과 낱말 줄바꿈은 실제로 함께 읽으며 판단할 후속 항목이다. 단색 보라 표지는 비용 없는 mock 생성 샘플이며 실제 AI 그림 품질 결함으로 집계하지 않는다.

## 공동 확인 순서

1. 홈에서 읽기 → 앞뒤 페이지 → 조작부 숨김/표시. 그림과 제목·본문이 겹치는지 확인한다.
2. 중간 페이지에서 닫기 → 서재에서 다시 열기. 읽던 쪽 복원과 마지막 장을 충분히 읽은 뒤 완료하는 흐름을 확인한다.
3. 짧은 주제 입력 → 12쪽 기본/8쪽 선택 → 허용 그림 스타일 → 생성 진행·검사·실패 안내를 확인한다. mock 테스트는 새 AI 콘텐츠 품질 검증을 대신하지 않는다.
4. 문제 신고 → 보호자 확인 → 사유 선택 → 접수. 개인 연락처나 문제 원문을 중복 수집하지 않는지 확인한다.

자동 검사 결과와 실제 실행 결과는 서로 구분해 기록한다. 최종 출시 전에는 실제 iOS/Android 기기, AI 제공자 이용 조건, 새 표본의 글·그림 품질, 운영 서비스 연결을 추가로 확인해야 한다. 정본은 [등록 전 공동 검토](PRE_REGISTRATION_REVIEW.md)다.

실제 실행에서는 기존 8쪽 책의 1~8쪽 이동, 중간에서 닫고 다시 열기, 마지막 장에 자동 축하창이 나타나지 않는 것, 명시적 완독 후 안내, 신고의 로컬 DB 접수까지 확인했다. 전체 API 회귀는 Python 3.12에서 **1,441 통과·14 건너뜀**이다. PostgreSQL/Celery나 실 AI 품질 검증을 이번 SQLite/mock 회귀로 새로 증명한 것은 아니다.

전체 Flutter 위젯·단위 회귀 **405개 통과**, 라인 커버리지 **52.85%**, `flutter analyze` 무이슈. 큰 글씨·짧은 화면·학습 콘텐츠가 있는 본문은 실제 드래그로 완료 동작까지 접근하는 검사도 포함한다.

iOS 26.5 시뮬레이터 통합 **4개 통과·1개 건너뜀**: 새 보호자 확인에서 신고로 전환, 신규 사용자 동의·온보딩, 재방문·부모 성장 화면, 실제 Keychain의 고유 테스트 키 저장/복원/삭제. 외부 서비스 fixture가 필요한 live backend suite 1개는 opt-in 미설정으로 건너뛰었다. 실제 운영 계정·실제 아동 사진·새 유료 AI 요청·스토어 업로드는 이 검사에 포함하지 않았다.
