# iPhone 실기기 검사 — 2026-11-02

연결·페어링된 iPhone 15, iOS 27.2에서 Xcode로 서명한 시험 앱을 사용했다. 검사 전 동일 앱 번들 ID가 설치돼 있지 않음을 설치 앱 목록으로 확인했다. 고객 계정·책·사진을 사용하지 않았고 서버에 합성 계정이나 책을 만들지 않았다.

- 실제 기기의 FlutterSecureStorage에서 시험값 쓰기·읽기·삭제가 성공했다.
- 별도 합성 네임스페이스로 앱의 `UserService` 신규 키 보관, 복구키 준비·활성화, 프로세스 캐시 초기화 후 다시 읽기 및 계정 삭제 완료 후 새 키 발급을 확인했다. 이 검사는 서버의 복구·삭제 트랜잭션을 호출하지 않았다.
- 두 단계 시험 앱을 실제 종료하고 새 프로세스로 다시 열었을 때 테스트 키가 보안 저장소에 남아 있는 것을 확인하고 해당 키와 마커를 삭제했다. 이는 iPhone 전체 재시동은 아니다.
- 기기의 기본 인증서 검증을 유지한 HTTPS 요청으로 비공개 시험 서버 `/health/ready` HTTP 200과 `healthy`를 확인했다. 인증서 오류 무시 설정은 사용하지 않았다.

일반 `flutter test`는 iPhone 앱 설치·실행 후 Dart VM Service를 발견하지 못해 완료되지 않았다. 따라서 테스트 결과는 디버깅에 의존하지 않는 서명된 임시 앱이 기록한 결과 파일을 기기에서 복사해 확인했다. 후속 반복 실행에서 시험 네임스페이스의 키를 지웠지만 테스트 앱의 초기화 마커가 남아 `UserKeyUnavailable`이 기록됐다. 이는 초기화된 계정의 저장 키가 없을 때 새 계정으로 대체하지 않는 동작이며, 앞선 독립 UserService 검사 성공과 분리해 기록한다. 반복 실험에서는 실제 이용자 데이터가 없었다.

이 결과는 네이티브 저장소와 서버 접근의 단일 표본이다. 완전한 실제 앱 화면·스토리 생성·미디어 재생·다양한 네트워크·기기·장시간 동작, 스토어 배포 또는 결제 검증을 의미하지 않는다. 결과 및 임시 시험 소스는 Git에서 제외된 `docs/acceptance/2026-11-02-iphone-device/`에 보관한다.


## 이후 유선 실기기 화면 검사

같은 iPhone을 유선으로 연결하고 사용자 기기 인증을 거친 뒤, 별도 임시 모바일 사본에 생성한 Profile 시험 앱과 XCTest로 필수 동의 스위치 선택·동의 내용 스크롤·제출, 온보딩 세 화면 이동과 시작, 빈 홈 화면과 서재 탭 표시를 확인했다. 최종 시험은 1건 통과했다. 초반 시도는 기기 인증 취소 또는 접근성 요소 선택 오류로 실패했으며 최종 통과에 합산하지 않는다. 시험 앱은 모의 API와 메모리 설정을 사용했으므로 운영 계정·실제 AI 생성·이미지·전체 낭독·스토어 거래를 검증하지 않았다. ## 실제 AI 시험과 낭독 후속 확인

같은 iPhone에서 실제 OpenAI 글·그림과 별도 시험 DB·저장소·작업자를 이용하는 가상 동화 생성 버튼을 눌렀다. 이 환경은 운영 사용자 데이터와 분리되고 접근은 임시 비밀 헤더로 제한했다. 기기와 시험 서버 간 응답이 지연되어 생성 요청 두 건이 접수됐으며 추가 요청을 중단했다. 한 작업은 제품 그림 품질 검사를 거쳐 완료됐고, 해당 작업만 다시 여는 임시 앱을 만들어 iPhone 실제 Viewer에서 표지·본문 1쪽 표시를 확인했다. 두 번째 작업 및 실제 호출 수는 별도의 서버 시험 기록을 따른다. 이 확인은 운영 API 연결이나 iPhone의 일반 생성 화면 전체 조작을 의미하지 않는다.

첫 본문 페이지에 낭독 버튼이 표시되지 않아 XCTest는 실패했다. 서버의 음성 지원 설정은 활성 상태였으나 기기에서 실제 capability 조회가 성공했는지는 확인하지 못했다. 기기용 진단 앱은 빌드했으나 iPhone이 다시 잠겨 실행하지 못했다. 실제 TTS 호출·전쪽 재생·자연 종료는 이 시험에서 검증되지 않았으며 오류 원인을 단정하지 않는다. 유선 및 Wi-Fi 시험에서 초기 요청 관측이 지연될 수 있으므로 다음 시험은 **동일 작업을 조회하여 이어가고, 생성 호출에는 안정적인 멱등성 키를 부여하며, 요청 접수 확인 전 재시도하지 않는다.**

재현 시에는 전용 합성 사용자와 일회용 접근 헤더가 있는 임시 백엔드에서만 실제 AI·TTS를 켠다. API capability 응답과 기기에서 소비된 capability 값을 각각 관측하고, 본문마다 서버의 음성 객체와 실제 iOS 플레이어의 재생·자연 종료를 확인한다. 기기 잠금 해제를 유지해야 하며, 테스트용 HTTP 접근 허용과 인증 설정을 제품 앱에 옮기지 않는다. 진단 앱과 테스트 러너는 설치 전 없음을 확인했고, 종료 후 해당 두 앱만 제거했다. 개인정보가 포함될 수 있는 Xcode 기기 진단 묶음은 저장소에 복사하지 않는다.

## Google 목소리 여섯 미리듣기 재검사

이후 같은 iPhone에서 별도 시험 앱의 실제 설정 화면, 번들된 Google 미리듣기 MP3와 iOS `just_audio` 엔진을 사용해 기본 여성 음색의 세 스타일을 각각 재생한 뒤 남성 음색으로 전환하여 세 스타일을 다시 재생했다. 여섯 재생 모두 `playing` 진입과 엔진의 `completed` 이벤트를 확인했고 XCTest 1건이 통과했다. 설정 API는 모의이며 실제 서버 연결·선택값 재실행 유지나 청각적 품질 판정은 이 검사에 포함되지 않는다. 새 AI 호출은 없다. [검사 결과](acceptance/2026-11-02-iphone-six-preview-recheck/result.json).

초기 시험에는 새 시험 앱의 로컬 네트워크 허용 창이 화면을 막은 사례가 있었고, 사용자가 직접 허용했다. 스크롤을 끝낸 직후 탭하는 시험과 접근성 요소 종류를 잘못 지정한 시험도 실패로 보존했다. 스크롤 안정 후 탭하고 올바른 요소를 확인한 후 통과했지만 이전의 모든 실패 원인이 같았다고 단정하지 않는다. 설치 전에 없던 시험 앱과 테스트 러너만 제거하고 미설치를 재확인했다.

## 2026-11-02 실제 iPhone 낭독 재시험

위 가상 4쪽 책의 본문과 그림을 별도 시험 DB·비공개 저장소에 복원하고 실제 OpenAI TTS로 네 쪽 음성을 만들었다. 기기에서 `audio_supported=true`와 첫 본문 화면을 직접 확인했다. 이전 재생 버튼 미발견의 재현된 원인은 iOS 접근성 레이블이 `오디오 재생`과 하위 `AI 낭독`을 함께 포함하는데 기존 시험이 전자를 정확히 일치하는 문자열로 찾은 것이다. 실제 화면에서 버튼이 존재함을 확인했으며 이전 실패 기록은 보존한다. 첫 시작은 capability 표시 시간 초과로 실패했고, 별도 시험 환경의 일일 한도가 2회라 3쪽에서 중단된 뒤 **합성 Redis 카운터만** 초기화하여 재시험했다. 제품의 실제 TTS 최대 6회 시험 가드는 유지했다.

실제 iPhone의 제품 Viewer에서 1~4쪽을 각각 눌러 재생 상태 진입과 종료 후 버튼 복귀를 확인했고 XCTest 1건이 통과했다. 같은 네 음성으로 수면 모드를 실행해 1→2→3→4쪽 자동 전환, 각 페이지 재생 상태와 마지막 버튼 복귀도 통과했다. 서버는 실제 OpenAI TTS 네 번 모두 HTTP 200과 음성 객체 네 개를 확인했으며, 연속 재생 시 추가 외부 TTS 호출은 시험 가드로 차단했다. 자동 전환의 1~3쪽은 플레이어 완료 이벤트에 의해 다음 쪽으로 이동했다. **마지막 4쪽은 버튼 복귀만 관찰했으므로 해당 표본의 오디오 엔진 completed 이벤트를 직접 확인한 것은 아니다.**

추가로 10월 23일 보존된 **다른 가상 책**의 본문·삽화와 당시 실제 TTS 4개를 기기 내에 복원해, 제품 Viewer의 수면 모드와 iOS 오디오 플레이어를 이용한 4쪽 자동 낭독을 실행했다. 시험용으로 표시한 실제 `ProcessingState.completed` 이벤트가 1~4쪽 모두 관측됐고 XCTest가 통과했다. 이 시험은 이전 표본의 플레이어 동작 증거이며 위 최신 책의 4쪽 완료 이벤트를 소급해 증명하지 않는다. 당시 테스트 스크립트는 저장된 본문의 `text`만 복원했고 실제 TTS에서 우선할 수 있는 `text_ko`는 별도로 복원하지 않았으므로, 그 음성이 표시된 본문과 일치하는지는 미검증이다. 두 시험 모두 테스트 전용 앱·합성 사용자 환경이고 운영 API나 스토어 구매를 검증하지 않았다. 음성의 발음과 내용은 사람이 청각적으로 평가하지 않았다. [비식별 시험 요약](acceptance/2026-11-02-iphone-live-narration/result.json).

사용자의 낭독 피드백 후 11월 가상 동화의 첫 본문을 정확히 입력해 개선된 1.0배 설정으로 OpenAI TTS 1회 호출해 MP3를 생성했다. 해당 첫 쪽 본문과 그림, 음성을 일회용 기기 내 Viewer에 표시하고 실제 iPhone에서 재생 시작과 플레이어 `ProcessingState.completed` 이벤트를 확인했으며 XCTest 1건이 통과했다. 오디오는 6.17초다. 입력 텍스트와 화면 텍스트는 일치함을 확인했지만 출력 음성의 모든 단어·속도 체감에 대한 독립 청각 판정은 별도다. 기존 사용자 데이터를 사용하지 않았고 운영에는 설정을 적용하지 않았다.
