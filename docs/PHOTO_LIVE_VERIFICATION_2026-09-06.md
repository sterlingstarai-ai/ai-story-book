첫 실행은 사진 분석 성공 후 대표 이미지 요청의 401로 중단됐다. 두 번째는 대표 그림 검수·승인·원본 파기까지 통과했지만 본문 1·5·7·11·12쪽의 이미지 권한 오류로 책 완성을 차단했다. 전체 삽화 검수에는 도달하지 못했다. 실패한 책을 읽기용으로 내보내지 않았고 두 격리 실행 환경은 모두 정리됐다.

기존 키는 대시보드에서 추가된 권한이 저장된 상태에서도 같은 요청에 권한 오류와 입력 검사 응답이 교대로 발생했다. 오류는 `api.model.images.request` 누락을 가리켰으나, 그 내부 원인을 권한 전파 지연이라고 확정할 수는 없다. 모델 조회·Responses·이미지 요청만 허용한 새 제한 키를 발급했고 생성 없는 입력 검사 3회가 권한 거절 없이 연속 통과했다. 새 키는 비공개 로컬 설정에 보관하고 기존 키는 보존했다.

세 번째 실행은 대표 그림과 12건의 책 이미지 요청(표지와 본문 11쪽)이 모두 HTTP 200이었지만 마지막 본문이 시작되기 전 공유 590초 생성 제한을 넘었다. 검증 도구가 이미지를 동시 1개로 제한한 탓에 608.81초가 걸렸으며, 본문 12쪽 요청은 외부 전송 전에 차단됐다. 최종 IMAGE_QUALITY_FAILED 코드는 이 실행에서 육안·자동 삽화 불합격을 뜻하지 않는다. 전체 그림 검수에는 도달하지 못했다. 제품 제한을 늘리지 않고 검증 도구의 동시 생성을 제품 기본 3개로 맞췄다.

수정된 네 번째 실행(book-v4-runtime)은 대표 그림 1장·표지 1장·본문 12장의 이미지 HTTP 요청과 LLM 6회가 모두 200이었다. 333.29초에 전체 삽화 검수에 도달했으나 첫 검수 응답 후 353.49초에 IMAGE_QUALITY_FAILED로 차단됐다. 이 시점은 공유 590초 제한 안이며 검수 요청 자체는 20.16초였다. 다만 원래 기록에는 제공자 거절·응답 형식 문제·검증된 그림 결함 등을 구분할 세부 사유가 없어 실제 원인은 미확정이다. 그림 품질 불합격이나 합격으로 단정하지 않는다.

초기 샌드박스의 Docker 접근 실패 준비 기록(book-v4)은 외부 호출 0건으로 보존했다. 네 번째 실행도 격리 환경을 정리했으며 실패한 자산을 완성 책으로 내보내지 않았다. 새 PDF나 개인 모음 항목은 만들지 않았다. 같은 전체 유료 생성 반복은 멈추고, 원문·그림·키가 남지 않는 제한된 실패 진단을 보완했다. 실제 사진 외부 처리와 닮음 검증은 여전히 제공자 조건 확인 후 수행해야 한다.

이번 실호출의 usage 기반 추정 합계는 $2.505104이며, usage 미확인 오류 6건의 예약을 유지한 보수적 합계는 $3.225104이다. 청구서나 비용 상한 보장이 아니며 추가 충전은 하지 않았다. 임시 키 매핑 파일은 제거했고 전용 제한 키는 비공개 로컬 설정에 보존했다. 운영 API 환경과 사진 기능 활성 상태는 변경하지 않았다.

## 실패 진단과 마지막 제한 검증

실패 시 제공자 거절·응답 형식 오류, 검수 형식/쪽수 오류, 검증된 쪽별 결함, 부분 수정 한도·시간 부족을 구별하는 제한된 진단을 추가했다. 미리 정한 단계·사유·오류 enum과 검증된 쪽 번호·결함별 개수만 기록한다. 원문·사진·URL·예외 문자열은 기록하지 않으며 기존 통과 기준·재시도·시간 한도는 유지한다. 악성 문자열과 로그 redactor 회귀를 포함한 집중 검사 198개, Ruff, diff check를 통과했다.

기존의 완전 가상 대표 그림 한 장을 13개 페이지 라벨과 동일한 중립 설명으로 전달하는 검수 응답 계약 확인을 한 번 실행했다. 13쪽 응답 파싱이 통과했고 생성 이미지 요청은 0건이었다(usage 추정 $0.057124, 위 합계에 포함). 이는 검토 모델과 13쪽 응답 형식이 작동함을 확인한 것이며, 서로 다른 장면의 12쪽 동화 품질이나 앞선 실패 원인을 증명하지 않는다. 같은 실패 책을 재생성하거나 실패 판정을 우회하지 않았다.
