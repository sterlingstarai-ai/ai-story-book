# 2026-11-12 스토어 데이터 신고 정리

## 확인 범위와 현재 상태

모바일 `1.0.0(5)`와 실제 제한 베타의 수집 경로를 대조했다. 이 기록은 앱 기능 추가, 공개 출시 승인, 법률 검토 또는 OpenAI ZDR 적용 증명이 아니다. 공개 개인정보처리방침·이용약관 문구는 변경하지 않았다.

- **Google Play:** 데이터 보안 9종의 세부 답변을 최종 저장했다. Alpha 빌드 5를 포함한 변경 14건의 제출 요청 후 사전 검사가 끝났고, 콘솔의 **검토 중인 변경사항·변경사항을 검토 중입니다** 표시를 확인했다. 승인·테스터 배포 완료가 아니다. [저장](../acceptance/2026-11-12-data-safety/play-data-safety-saved.png) · [검토 중](../acceptance/2026-11-12-data-safety/play-in-review.png)
- **Apple:** 기존 7종에 기기 ID·구입 내역·성능 데이터·기타 진단 데이터를 더한 **11종**을 사용자의 최종 게시 승인 후 게시했다. 추가 4종은 앱 기능 목적·사용자와 연결·추적 안 함이다. 실제 연락처·접근 메모·기존 심사 패스를 저장하고 빌드 5를 제출해 심사 대기를 확인했으나 이후 `ITMS-91061`로 잘못된 바이너리가 됐다. 이 오류는 스토어 신고와 별개인 SDK 파일 누락이며 빌드 6의 수정·재제출 상태는 [별도 기록](ios-sdk-manifest-fix-2026-11-12.md)을 따른다. [개인정보 게시 확인](../acceptance/2026-11-12-data-safety/apple-privacy-published.png)
- 보호자 실제 SMTP 연결은 미검증이며 이메일 동의 기능은 꺼진 상태를 유지했다. 자격 입력 오류를 별도 진단 중이고 사용 가능한 실제 자격은 아직 확보하지 못했다. 연결 안내 도구의 집중 검사 28개 통과는 실제 메일 발송·수신 검증이 아니다. 실기기 후속 검사는 다음 연결 때로 보류했다. 받은 심사용 실제 전화번호는 Apple에 저장했으며 이 문서에는 기록하지 않는다.

스토어 진행 상태는 담당 주 에이전트의 콘솔 직접 관측에 근거한다. 아래 코드·설정 대조는 읽기 전용 감사이며 스토어 심사의 적정성이나 공급자 계약 전체를 인증하지 않는다.

## Google Play 9종

모두 **수집함·임시 처리 아님**으로 저장했다. 자체 서버·서재·독서 기록 등에 보관되는 데이터이므로 AI 제공자의 보관 설정만으로 임시 처리로 분류하지 않는다.

수집 목적은 실제 기능·계정 관리·맞춤설정·분석·보안의 해당 범위로 한정하며 광고·마케팅 용도로 신고하지 않았다. 외부 공개 API와 미디어는 HTTPS를 사용하고, 앱 내 계정 삭제와 공개 삭제 안내 경로를 제공한다.

**보호자 이메일을 필수 동의 절차로 활성화할 때는 이메일 수집의 필수 여부를 함께 갱신해야 한다.** 현재 비활성·선택 문의 상태를 미래의 필수 메일 수집과 혼동하지 않는다. 발송업체·보관 조건·공개 방침·스토어 신고도 실제 활성화 구성과 일치시킨다.

### 공유 예외 판단

Google은 개발자의 지시에 따라 대신 처리하는 서비스 제공자 및 사용자가 직접 요청하고 예상하는 전송에 공유 신고 예외를 둔다. OpenAI DPA는 고객을 대신하는 처리자 역할과 고객 지시를 명시한다. 이 근거와 실제 앱 경로를 대조해 9종을 공유 안 함으로 저장했다. 이는 OpenAI·Google Cloud·Neon으로 전송하거나 위탁하지 않는다는 뜻이 아니다. 향후 독립적인 광고·학습·마케팅 사용 등 실제 처리 조건이 달라지면 예외 적용과 신고를 다시 대조한다. ZDR 적용 여부와 공유 예외는 별개의 판단이다.

- [Google 수집·공유·임시 처리·필수 여부 정의](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)
- [OpenAI DPA: 처리자 역할과 고객 지시](https://openai.com/policies/data-processing-addendum/)

## Apple 분류와 매니페스트 대조

기존 7종은 고객 지원·기타 사용자 콘텐츠·이름·기타 데이터 유형·제품 상호작용·사용자 ID·이메일 주소다. 현재 콘솔에는 추가 4종까지 11종을 저장·게시했으며 추가 항목의 추적 목적은 선택하지 않았다.

- **기기 ID:** 계정에 연결되는 기기별 자격 검증값. 광고 식별자는 수집하지 않는다.
- **구입 내역:** 기존 StoreKit 거래의 복구·검증 경로. 신규 구매 비활성과 독립이다.
- **기타 진단 데이터:** HTTP 요청 상태·오류·처리 시간 등 기술 진단 기록.
- **성능 데이터:** 실제 서버 HTTP 요청의 `duration_ms`·지연을 성능 관측의 넓은 범위로 공개하기 위해 유지한 분류다. iOS 실행 시간·무반응률·에너지 사용을 수집한다는 설명이 아니다. 기술 진단에 한정하는 최소 분류도 검토했지만, 담당자는 실제 요청 성능 저장 범위를 드러내는 11종 유지안을 선택했고 사용자가 게시를 승인했다. 이 4종 모두가 유일한 필수 분류라고 단정하지 않는다.

빌드 5의 실제 IPA에서 개인정보 매니페스트 16개를 파싱했다. 모두 추적 `false`·추적 도메인 없음이며, SDK 수집 선언은 Kakao common의 기타 데이터 유형·사용자 연결·앱 기능뿐이었다. 나머지 15개는 수집 배열이 비어 있었다. 파일 시각·부팅 시각·UserDefaults의 required-reason API 선언 자체가 서버 수집이나 기기 ID 수집을 뜻하지 않는다. SDK의 빈 수집 선언은 앱 자체 서버 처리를 대신하지 않는다.

클라이언트 `AppTelemetry`·`LoggingAnalytics`는 로컬 개발자 로그이며 원격 충돌 보고 SDK/업로드는 확인하지 못했다. 따라서 충돌 데이터를 자동 추가하지 않았다. 사진 업로드·새 사용자 음성 녹음은 현재 베타에서 비활성이다. AI가 만든 그림·낭독의 서버→기기 다운로드와 사용자의 사진·음성 업로드 수집을 구분한다. `store=False`는 요청 보관 설정이며 ZDR 적용 증명이 아니다.

## 남은 확인

Play 심사 결과·실제 테스트 배포와 Apple의 SDK 수정 빌드 처리·심사 진행을 확인한다. 보호자 실제 메일·승인 흐름, 다음 기기 연결에서의 최신 빌드·전권 낭독은 별도 확인한다. 이 신고 저장·게시로 앱 전체 검증·법률 검토·무중단 백업 또는 공개 출시가 완료된 것은 아니다.

## 심사 접속과 기존 운영 책의 후속 서버 검사

Play Console에 저장된 기존 심사 전용 패스를 메모리에서 읽어 운영의 해시와 읽기 전용 상수 시간 비교로 대조했고 `MATCH`를 확인했다. 원문을 파일·보고서·로그에 저장하거나 출력하지 않았고, 새 자격 발급·운영 변경은 없었다. 비교용 일회성 비공개 해시 파일은 제거했다. [대조 결과](../acceptance/2026-11-12-data-safety/review-pass-match.json)

앞서 만든 같은 운영 책의 5–12쪽을 합성해 저장 음원 12쪽 모두를 서버에서 확인했다. 총 339.25초, 마지막 쪽 30.55초이며 24kHz 모노 16비트 WAV의 형식·해시·캐시 일치를 검증했다. 새 책 생성, 잔액 변경, 작업 수 증가, 한도 초기화는 없었다. 공용 일일 한도는 14를 유지했고 사용량은 0→12였다. 추가 합성 HTTP 요청은 8회였으며 추가 소비 4회의 원인은 이번 기록에서 단정하지 않는다. **서버 음원 생성·무결성 결과이며 실제 기기의 전권 재생·청취 성공이 아니다.** [서버 결과](../acceptance/2026-11-12-existing-book-narration/result.json) · [로컬 WAV 검사](../acceptance/2026-11-12-existing-book-narration/local-verification.json) · [준비 상태](../acceptance/2026-11-12-existing-book-narration/final-readiness.json)
