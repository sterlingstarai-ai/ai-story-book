# 유료 기능·음성·인쇄 연결 현황

2026-09-08. 사용자가 운영 연결·실기기 검증·유료 결제·음성·인쇄로 범위를 확대했고, 이어서 **결제는 나중에 하고 배선부터 준비**하도록 지시했다. 이전 문서의 무료 베타 한정 목표를 이 요청이 대체한다. 유료 리소스 활성화·스토어 제출·실물 주문은 이번 작업에서 하지 않았다.

## 연결된 코드

- 운영: 기존 Render API/worker/Redis 템플릿 및 외부 DB·비공개 Storage 연결을 유지. 새 OpenAI 음성 설정도 API와 worker에 전달한다. 비밀값을 이미지나 모바일에 포함하지 않는다.
- 디지털 결제: 기존 StoreKit/Play 상품 조회 → 부모 확인 → 구매 → 서버 영수증 검증 → 크레딧 지급 → 소비/완료 흐름과 복원 경로를 회귀 검사했다. 실스토어 상품 등록·계약·영수증 자격증명을 대신했다고 보지 않는다.
- 음성: `TTS_PROVIDER=openai`와 명시적인 `OPENAI_TTS_API_KEY`, 모델·내장 음성 설정을 추가했다. 한국어 등 지원 언어·입력 길이·내장 음성만 허용하며 빈 오디오/오류 응답을 성공으로 저장하지 않는다. 기본 모델은 `gpt-4o-mini-tts`, 음성은 `coral`. 아이 목소리 복제는 하지 않는다. 앱에 AI 낭독 표시를 추가했다.
- 음성 오류 로그에서 제공자의 응답 본문을 제거했다. 본문에 동화나 입력 음성이 포함될 수 있기 때문이다.
- 가정용 인쇄: 기존 PDF 다운로드 → OS 인쇄창 연결이 있다. 이번 검사에서는 프린터 출력·종이 품질을 검증하지 않았다.
- 제작·배송 주문: 기존 Printful draft 제출/멱등 재시도/상태 조회 배선이 있으나 **동화책 내지 인쇄·실제 결제·배송까지 완성된 기능은 아니다**. 다른 제공자를 설정해도 Printful로 조용히 보내던 경로를 차단했다.

## 비용 없이 활성화 준비 검사

```bash
./scripts/final-external-preflight.sh --env-file infra/.env --check-planned-features --json
```

이 옵션은 세 기능을 켤 때 필요한 설정을 메모리에서만 검사한다. 원본 env, 기능 플래그, 계정, 비용을 변경하지 않는다. 설정이 채워져도 `launch_ready`는 false이며 외부 증거가 별도로 필요하다. 현재 운영 env는 실제 서버/저장소/스토어/인쇄 자격증명과 공개 정책 URL이 없어 BLOCKED다.

## 회귀 검증

- 결제·POD·외부 배포 관련 기존 회귀 180개 통과. 수정 후 음성·POD·활성화 검사 집중 회귀 98개 통과(서로 겹치는 테스트가 있으므로 합산하지 않는다).
- 모바일 결제 흐름·기능 표시 테스트 21개 통과. AI 낭독 표시 단언을 추가한 후 뷰어 8개 재검사 통과.
- env 계약 검사·Ruff 통과. 이 수치는 모의 제공자 검사이며 실제 결제나 인쇄 성공률이 아니다.

## 실연결 관찰

- Render: 로그인 유지, 서비스 0개, 카드 미등록. 확인 탭을 닫았다. 사용자의 결제 보류 지시에 따라 활성화하지 않았다.
- 음성: 기존 LLM OpenAI 키를 프로세스 안에서만 음성 키로 사용해 일반 문장을 호출했지만 HTTP 401로 거절됐다. 인증된 음성 키 연결 후 다시 검증해야 한다. 음성 품질·STT 왕복 성공으로 기록하지 않는다. 아동 사진·개인 정보는 보내지 않았다. 추가 충전은 없었다.
- iPhone: 페어링된 iPhone 15가 unavailable이다. Android adb도 PATH에서 찾지 못했다. 실제 기기 E2E 완료로 기록하지 않는다.

## 외부 연결 전에 남은 기술·운영 작업

1. 운영 계정 결제수단과 비용 확정 후 실제 서버·DB·Storage·HTTPS를 만들고 이미지 SHA, 큐, 서명 미디어, 삭제·백업 복원을 확인한다.
2. StoreKit/Play 실제 상품과 서버 알림을 연결해 샌드박스 구매·취소·환불·복원을 확인한다. 공동 최종 검토 전 심사 제출·공개는 하지 않는다.
3. 음성 키를 연결하고 생성된 책 낭독·페이지 이동·중단·이어 듣기를 실제 앱에서 검증한다.
4. 실물책은 제공자와 제본 상품을 확정하고, 해당 규격의 내지/표지 PDF, 실제 견적, 고객 결제, 주문 확정, 배송 추적, 취소·재제작 처리를 연결해야 한다. Printful 상품 ID만 넣으면 완성된다고 안내하면 안 된다. Lulu는 대안으로 조사했지만 어댑터를 구현하거나 계정을 생성하지 않았다.
5. 실제 iOS/Android가 연결되면 운영 빌드 전체 흐름을 재검증한다.

## 공식 문서

- [OpenAI Speech API](https://developers.openai.com/api/reference/cli/resources/audio/subresources/speech/methods/create): 입력·내장 음성·MP3·속도 설정.
- [Lulu 인쇄 API](https://www.lulu.com/sell/sell-on-your-site/print-api), [상품 규격](https://www.lulu.com/print-api/products): 맞춤형 책 인쇄 대안. 제본별 최소 쪽수와 상품 규격을 실제 책에 맞춰야 한다.
- [Lulu 주문 거절 원인](https://help.api.lulu.com/en/support/solutions/articles/64000306380-why-has-my-print-job-been-rejected-): 내지/표지 URL, PDF 규격, 상품 ID 및 배송 수단을 함께 검증해야 한다.

이 문서는 구현·검사 범위와 남은 연결의 기록이며, 모든 유료 기능 완성 또는 출시 승인서가 아니다.
