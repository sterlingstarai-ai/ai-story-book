## 실제 사진 선택기와 모의 AI의 경계

사진 선택기 검증은 플랫폼 대역을 사용하지 않았다. 정상 앱에서 실제 iOS Photos 선택기를 열고 보호자가 제공한 시험용 사진을 선택했으며, 요청한 이름의 캐릭터가 표시되고 승인되는 것을 확인했다. 승인 뒤 책 생성 화면으로 이동했고, 선택 사진의 임시 캐시 파일은 **0개**, 캐릭터의 원본 사진 URL 참조는 제거된 상태였다.

**이 사진 선택기 검증의 AI는 전부 모의 제공자였다.** 원본 사진을 외부 AI에 전송하지 않았으며, 실제 사진 변환 품질의 추가 성공 표본으로 계산하지 않는다. 앞선 자동 네이티브 사진 여정은 합성 PNG를 주입했으므로 실제 선택기 검증과도 구별한다.

실제 의존성 검증에서는 보관 중인 대표 캐릭터 파일을 그대로 재생했다. 캐릭터 새 생성 없이 승인 버전과 바이트가 책의 고정 참조로 유지되는지 확인했으며, 이야기·본문 삽화·자동 검수는 모의였다. 다른 계정의 열람·승인·책 선택 차단, 원본 파기, 캐릭터 삭제 후 기존 책 참조 보존, 이후 동의 철회에 따른 파생 책·파일 파기도 통과했다.

확인한 네이티브 화면에는 Flutter 오류 화면이나 레이아웃 넘침이 없었고, 독서 화면의 제목은 삽화 위의 별도 영역에 표시됐다. 캡처의 모의 그림은 실제 동화 삽화 품질을 보여주는 자료가 아니다.

## 수정한 기능 결함

1. **같은 사진의 재선택이 새 작업으로 취급될 수 있던 문제:** 사진 선택기는 같은 사진에도 새 임시 파일명을 줄 수 있다. 재시도 판별을 파일 경로에서 실제 파일 바이트의 SHA-256과 요청 필드로 변경했다. 응답 유실·타임아웃 뒤 같은 사진을 다시 선택하면 기존 멱등키를 유지하고, 다른 사진은 새 시도로 구분한다. 두 진입 경로의 수정 전 실패를 재현한 뒤 회귀를 통과했다.
2. **선택 사항인 이름을 비워 확인하면 업로드가 취소되던 문제:** 확인한 빈 이름과 취소를 구분하고, 빈 이름으로 확인한 경우 API의 선택 필드를 생략해 생성하도록 수정했다. 사진·그림의 빈 입력 및 공백 입력 4개 사례가 수정 전 실패했고, 수정 후 관련 39개 회귀를 통과했다. 명시적 취소는 업로드하지 않고 선택 캐시를 정리한다. [이름 입력 회귀](acceptance/2026-09-07-app-function-native/empty-name-regression.json).

실제 삽화에서 발견한 모호한 지시도 생성 템플릿에 반영했다. 여러 행동 중 한 순간을 선택하고, 가리키는 손과 대상 사이의 가림을 피하며, 반복 소품의 중심 문양을 구체적으로 유지하도록 보완했다. 이 생성 지시 변경은 아래 후속 검수 기준 조정과 구분한다. 기존 골든 생성 구조·그림 프롬프트 계약 검사 **34개가 통과**했고, 이후 검수 지침까지 반영한 집중 회귀는 **133개 통과·실패 0**, Ruff도 통과했다. 이 검사는 수정 템플릿을 사용하는 새 책의 실제 오류율 개선을 입증하지 않으며, 아래 실호출은 이미 생성된 장면 설명을 사용한 별도 표본이다.

네이티브 자동화에서는 화면 밖 목록 항목을 먼저 스크롤하고, 프로필 이름 입력 뒤 키보드가 닫힌 다음 연령 선택기를 조작하도록 대기 처리를 보강했다. 이 자동화 탐색 실패는 위 두 제품 결함과 구분한다.

## 보호자가 읽는 수준의 검수 기준

사용자의 요청에 따라, 일반적인 화면 크기에서 읽을 때 보이는 명확한 오류를 기준으로 지침을 조정했다. 본문이 허용하는 한 순간이면 충분하고, 앞선 허락·확인 대화가 그림에서 생략됐다는 이유로 규칙 위반을 추정하지 않는다. 세부 시각 지시는 본문의 모든 문장을 동시에 묘사해야 하는 체크리스트가 아니다. 작은 무늬·주름·장식 차이는 허용하지만, 인물 교환·복제·읽을 수 있는 문자·중심 행동의 모순·위험·판독 불가는 계속 차단한다. 검수 횟수·부분 보완 한도·자동 실패 차단 코드는 바꾸지 않았다.

검수 모델은 Sol을 유지했다. 새 기준으로 사전에 선택한 세 표본을 각각 한 번만 검사해 **최신 13장 전부 통과**, 기존 문자 오류 책의 **2쪽에서 인쇄 지시문·읽을 수 있는 문자·인물 교환 검출**, 기존 행동 오류 책의 **2·3쪽에서 행동 불일치 검출**을 확인했다. HTTP 200 세 건이며 새 이미지나 재시도는 없었다. 같은 요청을 통과할 때까지 반복하지 않았다. 선택한 세 표본의 관측이며 일반적인 오탐·누락률의 통계 추정은 아니다. [기준 교정 실호출 기록](acceptance/2026-09-07-human-threshold-review/result.json).

## AI 역할과 저장소

최초 결정은 Gemini 3 Pro Image가 그림을, GPT-5.6 Sol이 글·검수를 맡는 구성이었다. Sol은 Claude 포함 4개 모델·24편 비교에서 한국어·서사·첫 요청 성공률·비용을 함께 보고 선택했으며 최저가여서 고른 것은 아니다. 이후 사진 캐릭터 편집 기능을 검증하는 격리 실행은 GPT Image 2가 그림을 맡았다. 동일 사진·동일 과제로 Gemini보다 우수하다고 입증한 최종 이미지 공급자 결정이나 운영 환경의 영구 전환은 아니다.

파일 저장은 별도의 비공개 S3 호환 저장소다. Gemini가 사진을 보관하는 클라우드 저장소인 것은 아니며, 원래 두 AI를 쓴 이유는 글·검수와 그림 생성의 역할 분담이다. 현재 사진 시험에서는 OpenAI의 서로 다른 글 모델과 그림 모델을 사용한다. [모델 선택과 전환 범위](AI_MODEL_DECISION_2026-09-06.md).

## 이름 재사용 — 제안 단계

현재 이름 입력은 **아이 프로필, 사진 캐릭터, 책 생성 화면의 주인공 이름** 세 곳에 있다. 캐릭터 승인 후 생성 화면으로 이동할 때 ID만 전달되고, 생성 화면은 선택한 캐릭터 이름이나 현재 프로필 이름을 자동으로 채우지 않는다. 서버에는 선택한 캐릭터의 이름이 유지되므로, 화면의 빈 입력란이 곧 캐릭터 정보 유실을 뜻하지는 않는다.

권장 방향은 최초 한 번 이름을 받고 이후 선택한 캐릭터·현재 프로필에서 자동 재사용하는 것이다. **이름 필수화나 자동 채움은 이번에 구현하지 않았다.** 현재 선택 사항인 이름의 빈 확인 결함을 수정한 것과 새 입력 정책 제안은 별개다. 적용 시에는 여러 아이의 프로필 전환, 직접 입력한 이름 보존, 선택 캐릭터와 책 요청의 이름 일치를 함께 검증해야 한다.
