코드에는 별도 GCS 증인 버킷의 명시적 선택 설정을 추가했다. 같은 버킷을 양쪽에 지정하면 시작에 실패하고, 백업 설정이 실제 API·worker의 기록 설정과 다르면 백업 전에 중단하도록 했다. 기존 서버의 두 서비스 설정을 읽기 전용으로 비교한 결과는 일치했다. 새 설정과 백업 변경은 아직 운영에 배포하지 않았다. 별도 프로젝트·권한·키 복구, 기존 이력의 운영 이관과 두 저장소에 대한 공통 실패/관리자 삭제 방어가 확인되기 전에는 증인 설정을 켜지 않는다.

Google Cloud 결제 예산을 읽기 전용으로 확인한 결과, 월 10,000원 알림은 현재 시험 프로젝트에만 적용된다. 같은 결제 계정에 새 프로젝트를 추가해도 이 프로젝트 지정 예산에는 자동으로 포함되지 않으며, 예산 알림은 지출을 자동 차단하지 않는다. 새 프로젝트만 만드는 것은 같은 Google 계정의 관리 권한이나 계정 상실로부터 독립적인 복구를 보장하지 않으므로, 별도 청구 프로젝트를 추가하거나 증인 저장소를 운영에 연결하지 않았다.

이번 변경 후 API 전체 회귀는 2,318개 통과, 27개 건너뜀이다. 이는 주로 모의 공급자·SQLite 시험이며 운영 복원, 실제 결제 또는 서비스 출시 승인이 아니다. 서버 내부 HTTPS readiness는 200이고 백업·백업 감시·외부 알림 타이머가 실행 중인 것을 확인했다. 사용 중인 외부 네트워크의 IP가 기존 소유자 전용 방화벽에 없어서 Mac에서의 HTTPS 접속은 별도로 확인하지 못했으며, 방화벽 허용 범위는 변경하지 않았다.

복원 격리 검사의 기초로, 지정한 이미지·컨테이너 식별자와 일회용 표식, 네트워크 없음, 비루트, 읽기 전용 루트, 제한된 메모리 파일시스템과 권한, 호스트 바인드·포트·로그 저장 없음 등을 검사하는 읽기 전용 도구를 추가했다. 실제 임시 컨테이너에서 외부 연결 차단과 메모리 저장소 쓰기를 확인하고, bridge 네트워크 컨테이너는 거부한 뒤 둘 다 제거했다. **복원 공개는 여전히 금지:** 현재 재적용기는 일회용 시험 DB·저장소 전용이다. 운영 사고 후 최신 외부 기록의 완전성을 독립적으로 증명할 수 없고 음성 재동의·새 샘플 복원 및 실제 운영 데이터에 대한 전체 삭제 전파가 완성되지 않았다. 비밀은 같은 Google 프로젝트의 Secret Manager에도 보관되므로 프로젝트 전체 상실에 독립적인 재해 복구 증거가 아니다.

현재 Google VM 시험은 합성 데이터만 사용한다. 실제 아동 데이터를 받기 전에 자동 백업과 삭제 이후 복구를 함께 완성해야 한다. 최신 삭제 이력과 인증 폐기가 이전 DB·미디어 백업에 포함되지 않을 수 있으므로 단순히 가장 최근 백업을 복구해 공개하면 삭제한 데이터나 자격증명이 되살아날 수 있다.

현재 `scripts/backup_external.py`는 백업 시작과 종료 시 활성 생성 작업과 미완료·실패·알 수 없는 상태의 저장소 삭제 지시를 차단하고, 그 사이 PostgreSQL 트랜잭션 스냅샷이 바뀌면 완성 세트를 폐기하며 미게시 개인정보 기록도 차단한다. 새 개인정보 기록 테이블이 없는 기존 운영 DB에서는 실패하므로 실제 마이그레이션 전 이 코드로 운영 백업을 실행할 수 없다. API 쓰기와 worker를 실제로 중지했는지 또는 백업 후 삭제가 발생했는지는 증명하지 않는다. 테스트는 PostgreSQL 16 격리 fixture 및 mock 실패 주입이며 자동 운영 백업은 아니다.

격리 PostgreSQL 15·비공개 MinIO 리허설에서 백업 후 합성 계정 삭제·동의 철회 및 원본 그림 삭제를 모의했다. 오래된 복원본에는 삭제 전 계정·동의·그림이 남는 것을 확인했다. 이 검사는 위험을 재현했으며 삭제 재적용이나 자동 백업을 구현한 것은 아니다.

## 구현·운영 게이트

1. 계정 삭제, 사진·동의 철회와 재동의, 개별 책·캐릭터·프로필·음성 삭제, 음성 동의와 공유 링크 철회, 미디어 파기, 복구키 교체·폐기를 각 변경 트랜잭션과 연결해 누락 없이 기록하고, 백업과 독립된 내구성 있는 최신 기록을 만든다. 기록에는 원본 사진·본문·비밀값이나 공유 토큰을 넣지 않는다. 음성 샘플 교체는 시험 기록에서 옛 음성의 보수적 철회로 처리하며, 교체 후 새 음성의 복원은 아직 지원하지 않는다. 전송 지연과 장애, 중복 재전송 및 원본 DB 상실 직전 이벤트를 다뤄야 한다.
2. 복원 시 최신 기록의 완전성과 범위를 증명하지 못하면 외부 접근·쓰기·작업 처리를 차단한다. 식별자 매핑과 인증 폐기는 복원본에 재적용하고 해당 미디어 삭제가 실제 완료된 후에만 수동 승인 가능한 상태로 전환한다. 복원 중 새 삭제·동의 변경이 있으면 경계를 다시 맞춘다.
3. 서비스 중지·진행 작업 종료·미완료 파기 확인·DB와 미디어 일관성 확인을 실제로 실행하고 실패 시 안전하게 서비스를 복원하는 예약 작업을 만든다. VM이 꺼진 동안의 예약 누락, 잠금 중복, 작업 시간 초과, 디스크 공간 부족, 비밀 관리, 알림과 복구를 검증한다.
4. 원격 비공개 저장소에 최소 권한으로 새 백업을 쓰고 무결성·복원 시험을 검증한다. 보존 기간과 삭제 정책에는 Google Storage의 기본 7일 soft delete와 기존 사본·복제본을 포함한다. 실제 삭제가 끝나기 전 삭제 완료라고 표시하지 않는다.
5. 합성 계정에 대해 **백업 → 계정 삭제·동의 철회·자격 폐기 → 과거 백업 복원 → 최신 변경 재적용** 순서로 DB 행·복구키·직접/서명된 이미지 접근을 확인한다. 최신 기록이 누락되거나 오래되었을 때 복원 서비스가 공개되지 않는 부정 경로, 장애·경합과 실제 서비스 규모의 RTO/RPO도 별도로 검증한다.

이 게이트가 완료되기 전에는 [Google 시험 운영 기록](GOOGLE_PILOT_OPERATIONS_2026-11-02.md)의 수동 복구 리허설 결과를 자동 백업, 삭제 전파 또는 공개 승인으로 해석하지 않는다.
