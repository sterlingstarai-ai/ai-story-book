## 수정 후 운영 증거

`c0bd591`의 Dockerfile 변경에 맞춰 고정 r8 이미지를 기반으로 네트워크를 끈 증분 후보를 만들었다. 두 가상환경에서 시험 패키지 4개, 두 기본 Python에서 pip가 제거됐으며 그 외 설치 패키지 이름·버전은 모두 전과 같았다. 앱 소스 142개도 변경되지 않았다. 후보 기동과 제공자 접근을 확인하고, 이전 이미지·설정·백업을 보존한 채 r9로 전환했다. 전환 중 502가 관측됐으므로 무중단 배포로 표시하지 않는다.

실제 r9 컨테이너 안의 소스 142개, Flare·선택 Sunburst 설정, 새 이미지의 백업 소스 연결과 유효 복구 명령을 다시 대조했다. 외부 준비 상태 200 영수증과 정확한 워커 응답을 확인했다. 실제 설치 목록에서 중복을 합친 280개 Python/Pub 이름·버전 조합을 OSV에 다시 조회했을 때 알려진 권고가 반환되지 않았다. 이는 조회한 설치 패키지의 당시 결과이며, 운영체제·번들 아카이브·네이티브 전이 코드나 전체 앱의 무취약 보증이 아니다.

## 경계 검토와 한계

- 보호자 이메일 요청은 계정 범위로 처리하고 전역·주소·계정별 발송 제한이 있다. 주소를 DB 동의 기록에 저장하지 않는다. SMTP는 검증하는 TLS 연결 뒤에만 인증·전송한다.
- 확인 링크는 짧은 무작위 토큰을 fragment에 담고 Redis에는 해시 키를 사용한다. 확인 페이지는 토큰을 주소 표시에서 제거하고 단순 GET으로 승인하지 않는다. 명시적 POST와 최신 요청·동의 버전·철회 시각 대조, CSP·프레임 차단·no-store가 유지된다. 이메일 링크만으로 법적 보호자 확인이 충분하다는 법률 판단은 범위 밖이다.
- 심사 슬롯은 기존 계정의 동의를 우회하지 않으며 동의의 DB 저장·독립 개인정보 기록 게시를 확인한 뒤 접근 패스를 배정한다. 실제 메일 인증 설정이 없어 운영에서는 기능이 꺼져 있다.
- 준비 상태는 실제 200·정상 본문·제공자 준비 상태를 검사한다. 30초의 콜드 재개 허용은 오류를 정상으로 바꾸거나 최근 성공 값을 재사용하는 변경이 아니다.
- 이 검토의 자동 검사 통과는 미확정 메일 처리·스토어 신고·실기기 확인을 대신하지 않는다. Play 초안의 공유 예외와 보유 조건은 최종 공급자 구성에 맞춰 검토한 뒤 제출한다.
