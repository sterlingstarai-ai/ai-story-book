# 실제 온라인 백업 전체 격리 복원 — 2026-11-12

판정: **선택한 실제 백업의 DB·미디어 전체와 현재 원본 H1 상태를 격리 환경에서 검증했다.** 운영 DB 교체나 복원 서비스 공개를 승인한 결과는 아니다. 원본 DB를 조회할 수 있는 조건의 검증이며, 독립 서명 head·모든 쓰기 경로의 완전성·원본 상실 후 최신성은 입증하지 않았다.

## 실제 검증 결과

- 정확한 manifest와 원격 완료 표식을 먼저 고정하고, GCS에서 DB와 미디어 67개 전부를 내려받는 동안 크기·SHA256을 검증했다. 임의의 최신 세트로 대체하지 않았다.
- 외부 네트워크·호스트 마운트·권한 상승이 없는 소유 PG16·MinIO 임시 환경에 DB와 전체 미디어를 복원했다. 복원 후 내용·목록 완전성·메타데이터를 다시 읽었고, 모든 미디어의 익명 접근이 거부됐다.
- 복원된 H0 58건의 전체 해시가 원격 표식과 일치했다. 현재 원본 DB의 read-only repeatable-read outbox와 두 미러의 이름·암호문·전체 사건 ID·본문 해시·연속 revision·게시 완료 상태를 대조했다. 실제 DB 연결의 TLS `verify-full`·필수 channel binding과 실행 중 API·워커의 원본 연결 일치도 검사했다.
- 격리 재적용 경로에서 기존 체크포인트의 계정 삭제·동의 상태·장치/복구 인증 검증값과 완료된 파기 대상의 부재를 실제 DB·저장소에서 확인했다. 현재 유효 사진 권한이 꺼진 생존 계정 18개에는 사진 파생 행이 남지 않아야 하는 보강 검사도 적용했다.
- H1을 **22:31:57.350–22:32:31.009 KST**에 새로 읽어 검사 전후의 전체 전송 내용과 원본 식별자가 같음을 확인했다. H0=H1=58건이며 백업 이후 추가 사건과 신규 재적용은 **0건**이다. 새 삭제를 만들어 재적용 성공으로 세지 않았다.

## 발견해 수정한 검사 공백

H0에 이미 포함된 사진 철회·일부 동의 기록은 동의 행만 확인하고 파기 지시가 없는 사진 파생 행을 놓칠 수 있었다. 현재 유효 사진 권한을 `privacy AND data_processing AND photos`로 계산하고, 꺼진 계정에 `Character.from_photo` 또는 `Job.photo_derived`가 남으면 격리를 유지하도록 보강했다. 잘못 통과하던 10개 경우를 재현했으며 정상 재동의의 현재 상태 보존 2개를 포함한 새 회귀 12개와 집중 모듈 **91개**가 통과했다. Ruff·diff 검사도 통과했다. [회귀 범위](acceptance/2026-11-12-photo-checkpoint-fix/verification.json)

나중에 세 항목 모두 재동의한 경우에는 두 출처 표시만으로 철회 전 사진과 재동의 후 사진을 구별할 수 없다. 현재 권한 검사를 과거 사진 세대별 파기 완료 증명으로 확대하지 않는다.

## 보존·정리와 남은 경계

운영 DB·미디어 쓰기, 원본 쓰기 차단, AI 요청, 정상 제공자 키·저널 암호키의 Mac 전송은 모두 0이다. 원시 덤프·미디어·H1 전송은 호스트 파일로 남기지 않았다. 소유 컨테이너·임시 build context·임시 base 태그를 제거했고 코드 전용 이미지와 비밀 없는 영수증은 보존했다. [정리 결과](acceptance/2026-11-12-full-media-h1-restore-current/cleanup.json)

정리 후 22:34:20 KST의 공개 `/health/ready` 조회도 HTTP 200이었다. 이 조회는 새 AI 합성이나 실기기 시험을 실행한 결과가 아니다. [공개 준비 상태](acceptance/2026-11-12-full-media-h1-restore-current/root-public-readiness.json)

처음 시도에서 전체 미디어 복원 후 VM의 보조 모듈 누락으로 H1 단계가 중단된 기록은 [기존 폴더](acceptance/2026-11-12-full-media-h1-restore/)에 보존했다. 최종 시도는 필요한 순수 helper의 정확한 원문·해시를 SSH 메모리 입력으로 전달했고, 키나 원본 서비스 설치를 변경하지 않았다.

서명된 독립 최신 head 배치·독립 관리자/복구 키 보관·모든 writer의 포함·최종 서비스 개방 검증은 별도다. 현재 원본과 미러가 함께 과거 상태로 돌아간 경우나 마지막 관측 이후의 사건까지 이번 검사로 증명하지 않는다. `restore_authorized`, `service_publish_authorized`, `signed_head_latest_verified`는 모두 **false**를 유지한다. 실제 운영 전환은 [복원 절차](BACKUP_RESTORE.md)의 별도 게이트를 따른다.
