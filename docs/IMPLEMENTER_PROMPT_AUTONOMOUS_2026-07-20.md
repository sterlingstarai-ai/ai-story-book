## 자율 실행 모델 (핵심)
- 사람이 웨이브 사이에 개입하지 않는다. **그 대신 아래 자기 게이트를 스스로 통과**해야 다음으로 넘어간다. 게이트를 건너뛰거나 결과를 위조하면 전체 산출물이 무효다.
- **작업 단위 = 웨이브**. 웨이브 안에서 티켓은 `depends_on`·§3.2 공유 불변식(같은 함수 동시 편집)을 지켜 순서화한다.

## 절대 규칙
- **`⚠ 핸드오프 검토 정정` 블록은 원 fix_steps/test_spec보다 우선.** 반드시 반영.
- **TDD 예외 없음**: 티켓마다 버그 재현 테스트를 먼저 작성해 **red(실패)를 눈으로 확인**한 뒤 수정해 green으로. "수정 전 red 확인"이 명시된 동시성/타임존/멱등 테스트는 절차를 반드시 지킨다. **red를 못 만들면**(테스트가 수정 전에도 green) 그 테스트는 무효 신호이므로 시임/monkeypatch로 실제 실패를 유발하거나, 불가하면 FIXLOG에 `FALSE-GREEN-RISK`로 기록하고 CTO 리뷰로 넘긴다(조용히 통과 금지).
- **최소 변경.** 범위 밖 코드·리팩터 금지. `§0.2` 범위 밖(기각 7건·미구현 제품기능) 손대지 말 것.
- **규범 결정은 §2 확정값대로.** §2에 없는 스펙-코드 충돌은 임의 해소 금지 → FIXLOG `NEEDS-DECISION` 기록 후 그 티켓만 보류하고 계속.
- **.env·secrets 접근·출력 금지.**

## 자기 게이트 (웨이브마다, 통과 못 하면 진행 금지)
```bash
cd apps/api && venv/bin/python -m pytest tests/          # 베이스라인 대비 회귀 0
cd apps/api && venv/bin/ruff check src/
cd apps/mobile && /opt/homebrew/bin/flutter gen-l10n && /opt/homebrew/bin/flutter analyze && /opt/homebrew/bin/flutter test
cd apps/api && alembic upgrade head && alembic heads      # head는 항상 단일이어야 함
```
- **착수 베이스라인**: 백엔드 434 pass / **1 known-fail**(`test_shared_openapi_contract_is_committed_and_current` — 로컬 `apps/api/.env`의 `APP_VERSION=0.2.0` 잔재). **W1에서 M8의 백엔드 정정을 먼저 처리해 그린 베이스라인을 만든 뒤** 나머지 착수. 이후 게이트는 "전체 그린"이 아니라 **"베이스라인 대비 회귀 0"**.
- **마이그레이션**: `down_revision` 하드코딩 금지 — `alembic heads`로 직전 head 확인 후 지정(총순서 §3.1). **money 데이터 삭제/상태변경 마이그레이션(M16·M17·H14·N1)은 SQLite로 검증 불가** → PG 컨테이너(`infra/docker-compose.yml`)에 중복/충돌 데이터를 시드한 뒤 `alembic upgrade`를 실행해 dedup 결과를 assert. 이 리허설 없이 해당 웨이브 done 선언 금지.
- **l10n**: 신규 사용자 노출 문자열은 ko/en/ja `.arb` 동시 + `gen-l10n`. 하드코딩 금지.
- **계약**: openapi.json 동기(계약 테스트 강제). **서버가 실제 수용하기 전 헤더/필드를 계약에 문서화하지 말 것.**

## 웨이브별 커밋 = 롤백 체크포인트 (푸시 금지)
- **각 웨이브를 자기 게이트 그린으로 마치면 그 웨이브를 하나의 커밋으로 만든다**(feature 브랜치, Conventional Commits, 예: `fix(iap): W1 크리티컬 3건 …`). 푸시하지 않는다. 이 커밋들이 CTO가 웨이브 단위로 리뷰·롤백할 체크포인트다.
- 커밋 메시지에 그 웨이브의 티켓 ID·추가 테스트·게이트 결과 요약.

## FIXLOG (필수 산출물 — CTO 리뷰의 입력)
`docs/FIXLOG_2026-07-20.md`를 만들어 **티켓마다 한 항목** 기록:
- 티켓 ID / 변경 파일 / 근본 원인 요약 / **추가·수정 테스트 파일명과 테스트명** / red→green 확인 여부 / 게이트 결과 / **가정·이탈·`FALSE-GREEN-RISK`·`NEEDS-DECISION`·`BLOCKED` 플래그**.
- 웨이브 종료마다 그 웨이브 소계(게이트 결과, 마이그레이션 리허설 결과) 추가.

## 보류·정지 조건 (조용히 넘어가지 말 것)
- **규범 게이트는 34/34 전건 확정됨(미결 없음)** — 전 티켓 착수 가능. 브랜드(G28·G29): 정본 도메인 **aistorybook.com** / 카카오 딥링크 수신 **1차 제외**(execution params 제거) / KAKAO_NATIVE_APP_KEY 주입 **xcconfig·CI 빌드변수** / en·ja 앱 표시명 **영문 'AI Story Book' 통일**. H27·M33·L19·L21은 이 값대로 구현.
- 수정이 티켓 범위를 넘거나, 두 티켓의 fix가 실제로 충돌하거나, 돈·안전 경로에서 스펙이 코드와 모순되면: 추측 금지 → FIXLOG에 기록하고 그 티켓만 보류, 나머지 계속.

## (참고) CTO 최종 리뷰 계획 — 구현 완료 후 내가 실행
