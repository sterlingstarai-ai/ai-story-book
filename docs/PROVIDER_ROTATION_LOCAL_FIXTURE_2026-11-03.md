# 제공자 교체 격리 가드 시험 — 2026-11-03

`scripts/run_provider_rotation_actual_guard_fixture.py`는 실제 `provider_rotation_quarantine.arm`과 `quarantine`을 호출한다. 기존 운영 컨테이너·자격·네트워크는 사용하지 않고 고유 이름과 라벨, `network=none`, 읽기 전용 파일시스템을 가진 로컬 Docker 컨테이너 네 개만 사용한다. 로컬 Python 프로세스에서만 임시 마커 경로와 허용 컨테이너 이름을 교체하며, Docker 조작 전 정확한 ID·이름·이미지·라벨·네트워크를 검증하고 소유한 컨테이너만 정리한다.

합성 시험에서 표식 기록 후 각각 기존 컨테이너 실행 중, 기존 중지, 새 API만 실행, 새 API·worker 실행, 새 worker에 restart 정책이 다시 붙은 상태에서 프로세스를 강제 종료했다. 실제 quarantine 호출은 기록된 네 컨테이너를 중지하고 restart 정책을 해제했으며 두 번 호출해도 표식은 남았다. 별도 시험에서 기록된 새 worker를 제거한 뒤 복구를 실행하면 실패로 보고하고 표식을 유지하면서 나머지 세 컨테이너도 격리했다. 소유한 컨테이너가 모두 제거된 것을 확인했다.

첫 시도는 `sleep`이 컨테이너 PID 1로서 종료 신호를 처리하지 않아 중단했다. 해당 네 컨테이너를 정리한 다음 종료 신호를 처리하는 셸을 사용해 위 시험을 다시 실행했다. 시험 스크립트 Ruff 검사도 통과했다.

이 시험은 로컬 Docker와 임시 마커를 사용한다. 실제 부팅·systemd 설치·ingress 차단·키 수신·제공자 호출·백업과 운영 복구 순서를 증명하지 않는다. 기존 운영 `arm` 차단은 그대로이고 실제 키 전달 기능은 구현하지 않았다. 현재 API의 글·그림 키 설정은 환경변수 기반이므로 Docker 환경 메타데이터, 명령 인자, 로그, 이미지와 임시 파일 등에 키가 남지 않도록 하는 별도 전달 설계 및 검증이 필요하다.
