## 확인 및 보완

Google VM 시험과 별도로 테스트용 저장소 이미지가 Quay에서 401로 내려받아지지 않는 문제를 확인했다. 공식 릴리스 바이너리의 amd64/arm64 SHA-256을 각각 확인하는 격리 시험 전용 Dockerfile로 E2E·복원 스크립트의 의존성을 교체했다. 두 아키텍처 이미지 빌드가 통과했고, 새 이미지로 Mac에서 [전체 PostgreSQL/Celery·미디어 runtime gate](acceptance/2026-11-02-runtime-full-minio-image/result.json)와 [합성 백업·복원](acceptance/2026-11-02-restored-minio-image/result.json)을 다시 통과했다. PostgreSQL 회귀 21개 및 실제 프로세스/비공개 S3 모의 여정은 운영 공급자 검증이 아니다. 기존 개발 및 운영 Compose의 Quay 참조는 별도 문제로 남는다.

추가 실행: [합성 데이터 백업·복원 리허설](acceptance/2026-11-02-backup-restore-synthetic/result.json)은 독립 PostgreSQL·비공개 S3에서 행/미디어 체크섬, FK·시퀀스, 삭제 대기, 폐기 인증 상태, 서명 다운로드를 확인하고 정리했다. 작은 합성 표본이며 운영 백업이나 RTO/RPO 증거가 아니다.

[실제 AI 가상 4쪽 시험](acceptance/2026-11-02-fictional-quality-review/result.json)은 실제 OpenAI 글·그림·검수와 격리 PostgreSQL/Redis/Celery/S3를 사용해 226.29초에 완료했다. 최초 1쪽 `action_mismatch`를 탐지해 해당 쪽을 보완한 뒤 전체 재검수에서 오류가 없었다. AI 보조 시각 검토에서 최초 도서관 내부의 물이 분명하지 않았고 보완 후 내부 물이 보였다. 다른 네 장은 바이트 그대로이며 최종 저장 그림 5장도 재검수 입력과 일치했다. [시각 검토](acceptance/2026-11-02-fictional-quality-review/visual-review.json)는 AI 보조 검토이지 독립 사람 검토가 아니다. 이 한 표본은 이전 실패를 지우지 않으며 합격률이나 출시 승인이 아니다. 실 아동 데이터 사용·추가 충전은 없었다. 사용 기록은 LLM 요청 8회·이미지 요청 6회이며 기존 유료 API 호출의 실제 청구액은 확인되지 않았다.

Neon용 `postgresql+psycopg` 설정을 외부 운영 preflight가 거부하고 백업 프로세스에 channel binding 옵션을 전달하지 않는 불일치를 수정했다. 백업은 DB 서버와 `pg_dump`·`pg_restore`의 major 버전이 다르면 시작 전에 차단한다. 관련 회귀 94개와 가상 검수 증거 캡처·가드 회귀 112개 통과. 기존 실 서비스가 자동으로 연결된 것은 아니다.

## 실패·수정 내역

1. API 최초 전체 검사에서 readiness의 무인증 요청 변경을 이전 테스트 픽스처가 반영하지 않아 3건이 실패했다. 읽기 전용 readiness에 사용자 키가 없음을 검증하고 동의 요청에서 소유자를 수집하도록 픽스처를 고쳤다. 해당 집중 검사 포함 재실행 통과.
2. 상태 점검 테스트 1건이 비용 카운터 조회에 실제 Redis 연결을 사용해 닫힌 이벤트 루프를 재사용했다. 상태 점검 자체의 테스트에서 비용 스냅샷을 격리했으며 집중 검사 및 전체 재실행 통과. 운영 Redis 동작 전체를 증명하지 않는다.
3. 이번 검토자가 작성한 첫 Neon 백업 시도는 `PGDATABASE`에 연결 URI를 넣는 오류로 실패했고 마이그레이션은 시작하지 않았다. 같은 오류를 격리 PostgreSQL에서 재현·수정한 뒤 사용자 소유 Neon에서 백업 목록 검사와 마이그레이션에 성공했다. 실패 기록은 `docs/acceptance/2026-11-02-neon-migration/result.json`에 보존한다.
4. 백업 목록 검사만으로 복원을 통과했다고 볼 수 없어 별도 복원했다. PG18에서 작성한 아카이브를 PG16에 그대로 복원하면 `transaction_timeout` 미지원으로 실패했고 PG16 `pg_restore`는 아카이브 버전도 지원하지 않았다. PG18 `pg_restore`의 SQL 출력에서 해당 설정 한 줄만 제거해 격리 PG16으로 복원하면 성공하며 원래의 public 관계 객체 0개를 확인했다. 향후 Neon 16 백업은 같은 major의 `pg_dump`와 `pg_restore`를 사용하고 전체 복원을 시험해야 한다. 이번 시험은 빈 마이그레이션 전 백업만 다뤘다.

## 검토 범위와 남은 작업

변경된 개인정보 동의, 요청 크기·생성 예산, Redis/Celery 연결, 저장소, 작업 복구, 결제 영수증·크레딧, 시리즈 소유권, 음성 캐시 및 배포 설정을 코드와 기존 테스트·운영 계약에 대조했다. 모든 코드 경로에 대한 독립 보안 감사나 완전한 실기기 수동 검사는 수행하지 않았다. 최신 그림 품질, 외부 운영 환경과 무료 한도, 복원, 실제 스토어 및 개인정보 정책 검토, 운영 연결 빌드의 사용자 공동 검토는 계속 열린다. 실물 제조·배송은 범위가 아니다.
