# 운영 VM IAP 읽기 전용 접속 — 2026-11-03

사용자 요청에 따라 `asb-free-test`의 운영 상태와 백업을 읽기 전용으로 조사했다. 서비스·컨테이너 재시작, 제공자 키 전달과 운영 데이터 변경은 하지 않았다.

- 이전 IAP 확인은 기본 연결 검사에서 지연돼 터널 불가라고 결론 내릴 수 없었다. `--iap-tunnel-disable-connection-check`로 로컬 포트를 연 뒤 실제 접속했을 때 SSH 배너가 왔다. SSH의 Ed25519 호스트 키는 로컬 `google_compute_known_hosts`의 해당 인스턴스 ID 항목과 일치했다. 최초 호스트 키 신뢰가 독립적으로 확인된 것은 아니며 이 사실을 숨기지 않는다.
- `/tmp/asb-access-session-7b814.py`는 별도 인스턴스 메타데이터만 대상으로 `InstanceKeyGuard`의 fingerprint CAS를 이용해 5분 유효 공개 SSH 행 하나를 삽입했다. 기존 다른 항목은 보존하며, 충돌 시 재조회한다. 삽입 뒤 strict host-key 검사 및 IAP 경유로 SSH를 수립하고, 그 행만 정확히 삭제한 뒤 다시 조회해 부재를 확인했다. 프로젝트 공통 메타데이터는 변경하지 않았다. 임시 개인키 파일은 연결 수립 후 삭제했다.
- 각 메타데이터 제출 전에 공개 행·대상과 `requestId`를 소유자 전용 저널에 원자적으로 기록·fsync하고, 응답받은 operation ID도 기록한다. 제출 결과가 불명확하면 즉시 조회 결과가 비어도 나중에 반영될 가능성을 배제하지 않고 정리 미확정으로 보고한다. 비정상 종료 후 자동 복구는 아직 구현하지 않았다. 만료된 키의 접근 제한과 메타데이터 행이 제거됐다는 사실은 별개다.
- 이번 호출의 인스턴스 측 자기 행 삭제는 확인됐다. 임시 private key 파일은 삭제했고 제어 소켓은 0700 임시 디렉터리 안에 두었다. 이 연결은 생성 프로세스에서 최대 15분만 유지되며 종료 시 소유 터널·SSH 프로세스와 임시 디렉터리를 정리한다. 비밀이 아닌 복구 저널은 Mac의 소유자 전용 Codex 디렉터리에 남는다. `/tmp` 스크립트는 임시 작업 도구이므로 시스템 정리에 의해 사라질 수 있다.
- 운영 VM의 API·worker는 실행 중이고 이미지 ID는 기존 기록과 같았다. readiness는 HTTP 503, `provider_runtime=unverified`; DB·Redis·스토리지 등은 healthy였다. 백업 서비스의 마지막 결과는 success / exit 0이고 관련 timer가 활성화돼 있었다. jobs 테이블의 읽기 전용 상태별 집계는 0건이었으나 Celery 대기열과 진행 중 HTTP 요청의 완전 배수는 입증하지 못했다.
- 후속 읽기 확인을 위해 같은 방식으로 두 번째 세션을 열고, 자기 인스턴스 SSH 행의 제거·재조회와 임시 키 삭제를 다시 확인했다. 조사가 끝난 뒤 제어 연결과 소유 임시 디렉터리를 종료·삭제했다. 두 운영 복구 unit은 enabled이며 로컬 unit 파일과 해시가 일치했지만, 운영 `backup_service_guard.py`와 `deploy_pilot_privacy.py`의 해시는 최신 로컬 스크립트와 달랐다. 운영 코드를 서버 메모리에서 구문 분석한 결과 backup 복구는 backup.lock을 사용하지만 narration/provider rotation 가드를 언급하지 않고, privacy rollback은 자체 함수에서 그 잠금이나 두 가드를 검사하지 않은 채 이전 컨테이너를 시작·이름 변경·재시작 정책 변경한다. 최신 로컬 가드가 운영에 이미 설치됐다고 가정하면 안 된다.
- 세 번째 읽기 전용 접속에서 `pilot-privacy.env`를 서버 메모리에서만 분석했다. 46줄 모두 `KEY=VALUE`, 중복은 없었고 따옴표 시작·변수 보간 표식·줄 끝 역슬래시·값 바깥 공백·CRLF·NUL은 관측되지 않았다. 키명과 값은 기록하지 않았다. 이 관측은 후속 전환 시 파일이 불변임을 증명하지 않는다. 자체 SSH 메타데이터 행 제거·재조회 후 접속했으며, 검사 종료 후 연결과 임시 디렉터리를 정리했다. 운영 config.py만 제한된 패턴 검사 후 0600 임시 파일로 받아 격리 개발에 사용하고, 사용 종료 후 소유권·해시 확인 뒤 삭제했다. 환경파일과 키 파일은 전송하지 않았다.
- 후속 읽기 전용 접속에서 운영 API 설정은 사진 처리와 음성이 모두 비활성이었고, 제공자는 글·그림 OpenAI, TTS·STT mock이었다. 비활성 음성 모델 필드는 실제 음성 구동 증거가 아니다. 운영 backup guard의 `BackupServiceGuard`에는 `_run_unlocked`가 없고 `_recover_unlocked`는 존재했다. 개인정보 rollback과 직접 helper의 AST에는 `flock`·`_locked` 호출이 없었고 marker unlink는 직접 Docker 명령 뒤의 소스 위치였다. 정적 순서는 중단 시 실행 완료를 보장하지 않는다. 이번 자체 SSH 행은 인증 직후 제거·재조회했고 제어 연결과 임시 디렉터리를 정리했다.

후속 운영 전환에는 최신 제공자 자격 검증, 모든 트래픽·worker 배수, 동일 이미지·최소 설정 overlay 및 mount 검증, 백업 잠금과 재부팅 시 복구, 노출된 옛 키를 다시 쓰지 않는 실패 경로가 별도로 필요하다. 이 접속은 실제 운영 키 교체나 출시 승인을 의미하지 않는다.
