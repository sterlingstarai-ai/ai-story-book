# 출시 전 [차단] 결정지 — 개발 착수 전 CTO/창업자 결정

> 근거: `docs/DEV_SPEC_2026-07-20.md` §2 규범 게이트(총 34) 중 **착수를 가르는 차단 결정만** 추림.
> 나머지(Tier C)는 개발자가 권장 기본안으로 진행하고 오너가 사후 확인. 각 결정에 **CTO 권장안**을 달았으니, 이견 없으면 "권장 채택"으로 일괄 진행 가능.

## Tier B — 권장안 확인 (기본안대로 진행, 이견 시만 변경)

돈·규제·계약·브랜드가 걸려 있으나 **명확한 최소 권장안이 있어** 오너가 반대만 안 하면 그대로 간다.

| # | 게이트 | 결정 | 권장(기본안) |
|---|---|---|---|
| B1 | G3 | SAFETY_INPUT 최종 실패 시 선차감 크레딧 | **전 실패 환불(관대)** — 부적절 입력 과금 유지를 원하면 그때만 분기 |
| B2 | G22 | 시리즈 계약 변경 승인 + 첫 권 진입점 | SeriesNextRequest style/target_age를 **Optional로 변경 승인**(기존 클라 호환). 첫 권 진입점 부재를 출시 범위에 포함할지 확인 |
| B3 | G11 | 오늘의 동화 테마 로컬라이즈 + Theme enum | **서버 topic_id-only + 모바일 arb 표시**(i18n 규칙 정합). enum에 courage/kindness/growth/imagination 정식 추가 |
| B4 | G16 | 규범 스펙 vs 코드 정본(진행률·타임아웃·SAFETY_OUTPUT 재시도·이미지 안전검사) | 표는 **코드 실측으로 스펙 개정**, 단 SAFETY_OUTPUT 재시도 2회·이미지 안전검사 배선은 **구현**(규범 우선). CTO가 항목별 확정 |
| B5 | G27 | iOS 취침 오디오: UIBackgroundModes(audio) vs wakelock | **A(백그라운드 오디오)** 권장 — 부모의 수동 잠금(취침 시 최다 행동)에도 오디오 생존. B(wakelock)는 수동 잠금 시 즉사+화면 상시 점등. (자기검토 MA13 반영) |
| B6 | G21 | 사진 동의 기록: fail-closed 중단 vs PATCH 부분갱신 API | **A(fail-closed)로 출시**(최소), 감사추적 강화가 필요하면 B |
| B7 | G24 | 계정 삭제 파기 실패 증적 | **A(status=partial+로그)로 출시**, 파기 증적 요건이 강하면 B(실패키 장부+재시도) |
| B8 | G14 | 스턱 잡 처리 | **A(즉시 실패+환불, 재생성은 사용자)** — 진짜 재시도(B)는 대형 |
| B9 | G15 | 표지 이미지 실패 시 잡 판정 | **A(경고+degraded 배달)** vs B(잡 전체 실패) — UX 방향 확인 |
| B10 | G28/G29 | 브랜드·도메인·앱 표시명 | 정본 도메인(aistorybook.com vs .app), en/ja 앱 표시명, 카카오 딥링크 1차 포함 여부 — **브랜드 입력 필요** |
| B11 | G31 | 캐릭터 프롬프트 언어 | master_description **영어 통일**(캐릭터 일관성) 승인, 프리셋 표시명만 로케일 |
| B12 | G34 | 결제 검증 실패 시 소모성 트랜잭션(C3) | **기본안(pending 유지+재검증, Android는 검증 후 consume)** — 비차단, 결제 담당 사후 확인 |

## Tier C — 개발자 재량 (비차단, 사후 확인)

G4(웹훅 미기록 처리 A) · G5(plan=free 거부 A) · G6(환불 회수 0클램프 A) · G8(sandbox 지급 allowlist A) · G12(streak/today 익명 유지) · G13(SLA fence만) · G18(rewrite 무효화 A) · G23(마일스톤 계정 1회) · G26(마이그레이션 후방호환 규율 채택) · G30(CI CVE CRITICAL blocking) · G32(안전 suggestions 접두어 l10n) · G33(경미 기술선택 5건). — 전부 권장 기본안 존재, 개발자 진행 후 오너 확인.

## 진행 방식

1. **Tier A 8건**을 결정(권장 채택 또는 개별 지정).
2. Tier B는 "권장 일괄 채택" 또는 반대 항목만 지정.
3. 결정 확정 후 `DEV_SPEC` §2에 결정값을 주입하고 개발자에게 핸드오프.
