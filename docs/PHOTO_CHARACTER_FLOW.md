# 확정한 사진 캐릭터 제작 흐름

첫 원본→동화 캐릭터 변환은 사진의 표현 방식을 보존하지 않는 전용 지시를 적용하며, 사진풍 결과는 부모 미리보기 전에 반려한다. 이후 승인 캐릭터의 고정 재사용 정책은 유지한다. [수정·단건 실검증 및 공식 규칙](PHOTO_STYLE_AND_POLICY_2026-09-06.md).

2026-09-06 사용자 확정. 부모가 사진으로 캐릭터를 한 번 만들고 승인하면 그 모습을 이후 동화에서도 고정해서 재사용한다. **책마다 캐릭터를 새로 만들거나 외형 후보를 다시 고르지 않는다.** 기존 앱·읽기 디자인·12쪽 기본/8쪽 선택·전체 삽화 검수 정책은 유지한다.

## 고객 경험

1. 보호자 확인과 사진 동의 후 사진 또는 그림을 선택한다.
2. 대표 캐릭터 그림 **한 장**을 생성하고 명백한 문구·중복 인물·깨진 형태 등을 검사한다.
3. 부모가 미리보기에서 닮음과 모습을 확인하고 `이 모습으로 만들기`로 확정한다. 마음에 들지 않을 때만 다시 만들거나 다른 사진을 선택한다. 같은 업로드의 생성은 최초 포함 최대 3회다.
4. 다음 책부터는 확정 캐릭터를 선택해 바로 진행한다. 얼굴·머리·기본 복장을 유지하고 장면·자세·표정을 바꾼다. 부모가 명시적으로 다른 캐릭터를 요청할 때만 새로 만든다.
5. 표지·본문 전체 검사 → 문제가 있는 그림을 각각 한 번 보완(본문12쪽 책은 최대3장, 더 짧은 책은 최대2장) → 전체 재검사 → 통과한 책만 완료한다. 캐릭터 확인은 전체 책 검사를 대신하지 않는다.

대표 그림은 `generating → preview → approved` 상태로 관리하며 실패는 `failed`로 표시한다. 미승인·만료·참조 누락은 책 생성을 막는다. 화면을 나갔다 돌아와도 서버 상태를 조회해 이어갈 수 있고, 네트워크 응답 유실 때문에 자동으로 유료 재생성을 반복하지 않는다. 그림을 실제로 불러오기 전에는 승인 버튼이 활성화되지 않는다.

## 고정 캐릭터와 책별 보관의 차이

- 승인된 캐릭터 버전은 불변이다. 새 책 제작이나 스타일 선택이 대표 캐릭터 재생성을 유발하지 않는다.
- 이야기 입력과 캐릭터 시트도 저장된 외모·복장·고유 특징을 사용한다. 승인 사진 캐릭터는 책마다 LLM으로 새 캐릭터 시트를 만들지 않는다. 사진 캐릭터 카드·목록·상세에는 내부 영문 생성 지시문 대신 짧은 상태 안내를 표시한다.
- 각 책은 **승인 그림과 바이트가 같은 파일 사본**을 자기 작업 경로에 보관한다. AI 호출은 추가하지 않는다. 저장소 복사·보관 비용은 별개이며 무료라고 주장하지 않는다.
- 책별 사본은 캐릭터 목록에서 캐릭터를 삭제해도 기존 책을 읽고 같은 모습으로 보완하기 위한 것이다. 사진 동의를 철회하거나 계정을 삭제하면 이 사본까지 파기 대상으로 찾는다.
- 정상 첫 시도의 12쪽+표지는 이미지 13장이다. 최초 캐릭터 1장을 더하면 첫 책은 14장, 같은 캐릭터로 N권은 `13N + 1`장이다. 사진 분석·그림 검사·재시도 비용은 별도다. 재생성 절감 효과는 아직 실측하지 않았다.

## 서버와 저장 처리

- 원본은 JPEG/PNG/WebP 정지 이미지로 디코딩 검증하고 방향을 보정한다. 최대 10MB·1,600만 픽셀, 긴 변 1,024px로 제한하고 새 JPEG로 재인코딩해 EXIF/GPS 등 메타데이터를 넘기지 않는다.
- 원본은 우리 비공개 저장소의 임시 사본이다. 승인 시 삭제 지시를 같은 DB 트랜잭션에 기록하고 실행한다. 승인하지 않은 업로드는 24시간 만료 후 정리한다. 삭제 실패는 영속 큐에서 재시도한다. 사용자의 사진 보관함 원본은 삭제하지 않는다.
- Celery/개발용 백그라운드 작업은 버전과 상태를 원자적으로 확인해 한 번만 실행한다. 같은 요청·승인 더블탭은 멱등 처리한다. 생성 도중 삭제·동의 철회·만료가 발생한 결과는 게시하지 않고 임시 산출물도 정리한다.
- `Job.photo_derived`와 고정 참조 URL/버전을 남겨 캐릭터 행 삭제 뒤에도 파생 책·실패 작업·중간 이미지를 찾는다. 응답에는 원본 URL을 반환하지 않는다.
- 최초 지원 범위는 사진에서 만든 주인공 한 명이다. 텍스트 조연은 기존 방식으로 사용할 수 있다. 여러 사진 인물을 한 참조로 조용히 합치거나 누락하지 않는다.
- OpenAI 이미지 어댑터는 참조가 있으면 `/images/edits`에 실제 이미지 bytes를 전달한다. 필요한 참조가 없거나 제공자가 지원하지 않으면 참조 없는 생성으로 우회하지 않는다. 생성 중 보완과 완성 후 수정도 같은 승인 그림을 사용한다.

## 실서비스 활성화 조건

사진·그림 분석은 글쓰기 제공자와 별도의 `PHOTO_ANALYSIS_PROVIDER`, `PHOTO_ANALYSIS_MODEL`, `PHOTO_ANALYSIS_API_KEY` 설정을 사용한다. 실제 처리에는 분석·이미지 생성·삽화 검사 전체의 아동 데이터 처리 조건을 확인해야 한다. `PHOTO_PROCESSING_ENABLED`는 그 확인 뒤 운영자가 여는 기능 스위치이며, 스위치나 API 키가 제공자 승인을 증명하지 않는다.

현재 구현의 관리형 경로는 OpenAI 사진 분석 + GPT Image 참조 편집 + OpenAI 삽화 검사다. 기본 스위치는 꺼져 있다. 세 제공자를 명시적으로 `mock`으로 설정한 로컬 검증은 가능하다. 아래 구현 검증 당시에는 모의 AI만 사용했으며 유료 제공자를 호출하지 않았다. 이후 실서비스 검증은 별도 기록으로 구분한다.

OpenAI의 아동 데이터 지침과 ZDR 적용 조건, 파생 캐릭터도 보호할 자료라는 판단은 [사진 처리 옵션 조사](PHOTO_TO_CHARACTER_OPTIONS_2026-09-06.md)에 정리했다. 부모가 사진을 올린다는 사실이나 만화로 바꿨다는 사실만으로 제공자 조건을 충족했다고 보지 않는다.

## 검증 범위

구현의 상태 전이·소유권·동의·중복 요청·승인 후 재사용·삭제·API 계약을 자동 검증한다. 실제 사진의 닮음, 여러 쪽에서의 인물 일관성, 부모의 첫 책 완성률과 실제 비용은 별도의 실검증이다. 기존 15권은 실제 아이 사진을 사용한 두 방식의 비교가 아니므로 새 방식의 품질 우위 근거로 재해석하지 않는다.

사용자와 앱을 함께 최종 확인하기 전 스토어 레코드 생성·업로드·등록·심사 제출을 진행하지 않는 기존 중단선은 유지한다. 추가 제품 방향 결정보다 구현 검증·실서비스 조건 확인·운영 연결이 남은 작업이다.

## 후속 실서비스 검증

후속 유료 검증은 출처를 확인한 **완전 가상 인물 이미지**만 사용해 격리된 환경에서 진행한다. 실제 계정 대시보드의 `Data Retention` 표시는 `None`이며 ZDR 적용이 확인되지 않아, 실제 아동 사진 처리는 기본 비활성 상태로 유지하고 외부 전송하지 않는다. 첫 이미지 요청의 HTTP 401 원인을 확인한 뒤 API 키의 필요한 `Images` 권한만 `None`에서 `Request`로 변경했다. 가상 표본의 생성·검수 결과는 실제 아동 사진의 닮음이나 출시 승인 근거로 합산하지 않는다. 진행 상태와 비용·검증 한계는 [후속 실서비스 검증 기록](PHOTO_LIVE_VERIFICATION_2026-09-06.md)에서 별도로 관리한다.
