## 2026-09-07 독립 QA 수정

- 생성 상태 조회와 변경 요청의 제한을 분리했다. 기본 읽기 120회/분·변경 10회/분을 코드·예시·운영 Compose·CI에서 일치시켰다. 거절 요청은 제한 해제 시간을 늘리지 않는다. 앱은 429·일시 오류에서 기존 작업을 유지하고 다시 확인한다.
- 잘못된 행동의 그림을 재생성 때 구도 참조로 쓰던 원인을 제거했다. 본문12쪽+표지의 총16회 이미지 예산 안에서 문제 쪽을 추가 보완하고 전권 재검수한다. 사람에게 명확한 오류를 통과시키는 방식으로 기준을 낮추지 않았다.
- 운영 `/health/ready`는 실공급자 이용 미확인 또는 알려진 잔액·인증 오류에서 503을 반환한다. 명시적 일반 입력 점검이 성공하면 관측 상태가 갱신된다. health 요청 자체는 과금하지 않는다.
- 앱의 설정·동의 전 화면에서 약관과 개인정보처리방침 전문을 오프라인으로 읽는다. 공개 URL 누락과 미승인 문서를 release/배포 사전 검사에서 차단한다.
- 삭제 응답 유실 후 재시작 복구, 이미지 디스크 캐시·오프라인 본문의 파기 재시도, 서버 필수 동의, 월 무료 지급·한도 안내, 캐릭터 이름 변경·관리 메뉴·프로필 표시, 생성 양식 보존, 오류 다국어·환불 안내와 입력 검증을 보완했다.

전체 항목의 채택·기각·잔여 한계는 [통합 검토](QA_RECONCILIATION_2026-09-07.md), 운영 동작은 [제공자 관측·그림 보완](PROVIDER_RUNTIME_AND_REPAIR.md)을 따른다.

## 공개 전에 남은 조건

1. **운영 환경**: 공개 HTTPS API, 비공개 저장소·DB·Redis·worker, 백업 보관과 운영 환경 복원, 운영 AI 사전 점검. 별도 로컬 PostgreSQL/MinIO 복원은 통과했다. 기존 계정 로그인은 완료되어 있으며 월 정기 호스팅은 사용자의 보류 지시에 따라 활성화하지 않았다.
2. **공개 정책**: 공개 운영자와 문의 이메일은 사용자가 제공한 값으로 반영했다. 실제 처리 업체·국가·연락처·보유 기간·백업 일정·시행일은 운영 계약과 일치하도록 확정해야 한다. 전문은 현재 검토본이며 법률 승인이나 ZDR 적용을 받았다고 표시하지 않는다. 지원 상담은 사용자가 직접 확인하며 자동 확인 작업은 삭제했다.
3. **공동 최종 확인**: 운영 환경을 연결한 빌드에서 사용자와 실제 기기를 확인한 뒤 스토어 등록·업로드·심사 제출을 진행한다. 현재 IAP·음성·POD의 비활성 상태를 유지한다.
